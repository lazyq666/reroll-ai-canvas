# Smart Canvas 节点自动避让规格

- 状态：Current；阶段 0–8 已实施并验证，人工验收通过
- 日期：2026-08-26（Asia/Shanghai）
- 范围：Smart Canvas 所有自动新增功能节点的初始落位
- 开发方式：在独立 Codex worktree 中实施

## 1. 背景

Smart Canvas 当前有多条节点创建路径，并各自计算位置：生成图片与批量结果、生成文字、反推提示词、快速添加、上传、粘贴、复制、节点包导入、图片工作台输出等。现有逻辑混用了固定偏移和多套局部搜索算法，安全距离、搜索上限、分区处理和批次行为不一致。

本任务建立统一的自动放置规则和一个深的 Node Placement 模块。调用方只表达“为何创建、从哪里创建、创建什么”，不再各自实现坐标搜索。

“长期可靠”在本规格中指尽量覆盖不同创建场景和用户行为，不以极端节点数量或单独的性能基准作为首要目标。

## 2. 目标

- 所有自动新增功能节点通过同一个放置接口获得初始位置。
- 默认不重叠，并为节点左右快速添加交互区保留空间。
- 保留用户明确落点、流程方向、分区范围、批次关系和复制集合的空间语义。
- 已有用户布局保持稳定，新节点不能通过自动整理移动普通画布中的既有节点。
- 异步任务从占位到成功、失败、重试和恢复期间保持相同节点身份、位置和外部占地。
- 放置计算为纯内存计算，可通过模块接口直接测试，不依赖 DOM、渲染、网络或持久化。
- 删除分散在业务调用方中的固定偏移、局部碰撞搜索和重叠回退。

## 3. 非目标

- 不自动修复旧画布已有重叠。
- 不限制用户创建后手动拖动、缩放或主动重叠节点。
- 不让连接线参与放置评分或碰撞判断。
- 不让手绘标注和画布文本参与避让。
- 不实现全局网格化或自动整理整张画布。
- 不改变连接线路由算法。
- 不把视口换算、浮层定位、手动拖拽和图片编辑器内部坐标并入 Node Placement 模块。
- 不负责宫格、水平、垂直或树状的主动选区整理；该职责由 [Selection Arrangement](smart-canvas-selection-arrangement.md) 定义。
- 不为本任务单独承诺 1,000/10,000 节点性能指标；实现仍不得因性能原因降级为重叠。

## 4. 已确认的产品规则

### 4.1 创建时避让

自动避让只在节点创建落位时执行。节点创建完成后，用户可自由拖动到任意位置，包括主动重叠。后续创建的新节点以画布当时的实际功能节点占地作为障碍。

### 4.2 既有节点不可移动

新建节点不得移动普通画布或分区内的既有节点。存在两个明确例外：

1. **Smart Group（编组）** 是用户主动选择的自动布局容器。向编组内新增成员时，可按该容器既有语义重新排列编组内成员并调整编组尺寸。
2. **实时协作竞争** 中，多个客户端基于同一快照选择同一空位时，权威提交顺序较早者保留位置，只重新安置后提交的新节点或新批次。

### 4.3 创建意图与优先级

放置请求分为三类：

1. **有明确落点**：拖放、画布菜单等操作携带用户指定的世界坐标。先最小化与落点的距离，再考虑对齐。快速添加拖线是显式手动布局入口，按 4.11 保留精确落点。
2. **有来源、无明确落点**：下游默认向来源右侧，上游默认向来源左侧。先保持方向，再考虑同层对齐，最后比较距离。
3. **无来源、无明确落点**：从当前视口中心附近寻找最近合法位置，再考虑附近对齐。

当一次操作同时有来源节点和明确落点时，明确落点优先于默认流程方向。用户从输出端向左拖线创建节点时，允许新节点留在左侧，不强制送回来源右侧。

### 4.4 安全占地

普通功能节点的碰撞判断使用交互占地，而不只是可见矩形：

- 左侧安全距离：100 画布世界坐标单位。
- 右侧安全距离：100 画布世界坐标单位。
- 上侧安全距离：48 画布世界坐标单位。
- 下侧安全距离：48 画布世界坐标单位。
- 同一 Generation Batch 内部间距：48 画布世界坐标单位；横向模式用于相邻列，纵向模式用于相邻行。

这些值不随视口缩放改变。左右距离用于保护输入/输出快速添加按钮及其悬浮热区。

手绘标注和画布文本既不作为障碍，也不使用上述交互占地。连接线完全忽略。

### 4.5 流程方向与对齐

没有明确落点时：

- 下游节点优先向右。
- 上游节点优先向左。
- 单个结果继续按来源方向与邻近对齐寻找位置；Generation Batch 的连续行列规则见 4.7。
- 不因左侧几何距离更短，就把普通下游结果放到来源左侧。

对齐只作为软偏好，不强制全局网格。合法候选中可偏好来源顶部或垂直中心对齐、兄弟节点成列、附近节点共享左边缘或上边缘。对齐不得违反明确落点优先级、方向、分区或不重叠规则。

### 4.6 分区

来源节点位于 Frame（分区）内时，新节点或批次优先在同一分区内寻找位置。若剩余空间无法完整容纳，则整个新节点集合放到分区外侧：

- 不自动扩大分区。
- 不移动分区内或分区外的既有节点。
- 同一批次不能一部分在分区内、一部分在分区外。
- 分区是空间容器，不作为实心障碍；分区内实际功能节点仍是障碍。

### 4.7 Generation Batch

Generation Batch 的布局只影响同一次生成产生的多个独立 Generation Output，不影响复制、粘贴、导入或其他刚性集合：

- Canvas 设置保存横向或纵向批次布局，默认横向；该值属于 Canvas，不进入跨 Canvas 的个人“最近一次 Generation Settings”偏好。
- 每次 Generation Run/Generation Batch 在创建 Pending Node 时冻结实际采用的方向，并持久化到该批次；并发重试、恢复、Undo/Redo 使用批次快照，不按当前 Canvas 设置重新推断。
- 横向模式：同批结果按稳定顺序排成一行，内部相邻 Node 间距 48；同一来源的后续批次在上一批下方另起一行，起点对齐，整批保持原子且不与旧批次交错。
- 纵向模式：同批结果按稳定顺序排成一列，内部相邻 Node 间距 48；同一来源的后续批次在上一批右侧另起一列，起点对齐，整批保持原子且不与旧批次交错。
- 先计算整批占地，再统一选位；其他 Node 不能插入批次内部。
- 创建、撤销、重做、Generation Recovery 和并发重新安置都以整批为单位。
- 来源位于 Frame（分区）时，能完整容纳则整批留在分区内，否则整批移到分区外；自动创建不扩大分区。

### 4.8 复制、粘贴和导入集合

复制、粘贴或导入多个节点时，将它们视为刚性集合：

- 保持所有节点原有相对坐标和连接关系。
- 保留用户刻意形成的集合内部重叠。
- 只对整个集合应用同一个平移量。
- 分区及其内容作为整体处理，不能把内容移出分区。
- 刚性集合不套用生成批次的纵向排列规则。

### 4.9 稳定占位和异步结果

节点首次出现时就必须确定稳定的最终外部占地：

- 图片和视频根据生成参数中的比例预留最终尺寸。
- 上传媒体取得可靠尺寸信息后再完成放置。
- 生成文字使用稳定卡片尺寸；超长内容通过节点内部滚动或用户主动展开处理。
- 加载、成功、失败、重试状态不得改变外部占地。
- 尺寸无法精确预测时，按该节点类型的保守稳定尺寸预留。

异步任务完成和应用重启恢复必须原位更新同一个占位节点：

- 节点 ID、位置和稳定尺寸保持不变。
- 成功、失败、重试、任务查询和恢复只更新内容与状态。
- 已持久化占位节点存在时，不重新避让。
- 只有旧数据确实缺失占位节点时，恢复流程才通过统一放置接口补建，并关联原来源节点。

### 4.10 搜索与失败

画布没有正常业务意义上的固定边界。`.world` 的 `6000 × 4000` CSS 尺寸不是节点坐标裁剪范围；视口和小地图会跟随实际节点范围扩展。

因此，在已有功能节点有限且几何数据有效时，放置算法必须继续扩展搜索直到找到合法位置。禁止达到固定轮数后回退到仍然重叠的位置。

只有节点坐标或尺寸数据损坏、无法形成有效几何时，才允许明确失败；不得静默叠放。

### 4.11 快速添加拖线精确落点

通过节点左右快速添加按钮拖线创建节点时：

- 拖动期间只显示连接引线，不显示节点尺寸或位置预览框。
- 引线终点始终跟随指针，不提前执行碰撞解析。
- 从输出端拖线创建下游 Node 时，用户松手点是新 Node 左边缘的垂直中点；从输入端拖线创建上游 Node 时，用户松手点是新 Node 右边缘的垂直中点。菜单切换文字、图片或视频类型时，该边缘中点不得改变。
- 即使新节点会与已有功能节点重叠，也不得自动避让或移动既有节点。
- 该入口属于用户显式手动布局；点击快速添加按钮创建仍使用来源语义和自动避让。

### 4.12 视口跟随

- 用户直接发起的创建、粘贴、拖放或快速添加，如果最终节点位于当前视口外，执行最小幅度的平滑平移，使新节点完整可见。
- 后台或异步任务完成时不改变视口；任务开始时创建的占位节点已经确定位置。
- 其他协作者新增节点时不改变本地视口。

### 4.13 撤销、重做与旧画布

- 放置结果属于创建事务的一部分。
- 撤销删除整次创建产生的节点和连接。
- 重做恢复当时已确定的精确位置，不重新运行放置算法。
- 多人协作期间原位置被其他已确认节点占用时，按实时协作竞争规则重新安置后恢复的新节点。
- 打开旧画布时保留所有历史坐标，即使已有重叠也不自动迁移或整理。

## 5. 操作案例矩阵

| 操作 | 创建意图 | 首选位置 | 冲突时行为 | 特殊规则 |
| --- | --- | --- | --- | --- |
| 在画布菜单创建图片、提示词、循环、分隔符 | 明确落点 | 菜单打开点 | 从落点寻找最近合法位置 | 用户直接创建，必要时最小视口跟随 |
| 从桌面拖入图片或视频 | 明确落点 | 鼠标松开点 | 从落点寻找最近合法位置 | 上传取得可靠尺寸后完成放置 |
| 从资产面板拖入素材 | 明确落点 | 鼠标松开点 | 从落点寻找最近合法位置 | 保持媒体比例 |
| 在没有目标节点时通过文件选择上传 | 无来源、无落点 | 当前视口中心 | 从中心寻找最近合法位置 | 用户直接创建，必要时视口跟随 |

| 在画布空白处右键粘贴 | 明确落点 | 右键菜单位置 | 整体平移至最近合法位置 | 多节点保持相对布局 |
| 粘贴画布内复制节点 | 明确落点或最后鼠标位置 | 指定点或最后鼠标世界坐标 | 刚性集合整体平移 | 无可用鼠标位置时退回视口中心 |
| 导入节点包 | 无来源、无落点 | 当前视口中心 | 刚性集合整体平移 | 分区与内容保持整体 |
| 单次生成一张图片或视频 | 来源、无落点 | 来源右侧 | 保持右向流程并成列搜索 | 创建稳定占位，结果原位更新 |
| 一次生成多个结果 | 来源、无落点 | 来源右侧 | 整批统一搜索 | Canvas 方向快照；横向一行或纵向一列；间距48 |
| Prompt Node 生成文字 | 来源、无落点 | 来源右侧 | 保持右向流程并对齐 | 稳定卡片尺寸，长文本内部处理 |
| 反推提示词 | 来源、无落点 | 图片来源右侧 | 保持右向流程并对齐 | Prompt 占位和最终内容原位 |
| 从输出快速添加按钮点击创建 | 来源、无落点 | 来源右侧 | 保持右向流程 | 左右交互安全距离100 |
| 从输入快速添加按钮点击创建 | 来源、无落点 | 来源左侧 | 保持左向流程 | 左右交互安全距离100 |
| 快速添加按钮拖线到空白处创建 | 来源 + 精确手动落点 | 用户落点 | 不运行自动避让 | 输出端保持左边缘中点；输入端保持右边缘中点 |
| 快速添加按钮拖线到已有节点上创建 | 来源 + 精确手动落点 | 用户落点 | 允许与已有节点重叠 | 不移动被覆盖的既有节点 |
| 图片编辑、扩图、拼图等生成新节点 | 来源、无落点 | 来源右侧 | 使用统一来源放置规则 | 删除调用方中的固定 `+240` 偏移 |
| 智能抠图或其他自动媒体输出 | 来源、无落点 | 来源右侧 | 单个或批次规则 | 统一稳定占位与恢复语义 |
| 来源位于分区内 | 来源或明确落点 | 同一分区内优先 | 无完整空间时整个集合移到分区外 | 不扩大分区，不拆分批次 |
| 通过编组小菜单新增成员 | Smart Group 范围 | 编组内部 | 由 Smart Group 自动布局 | 允许重排编组内成员，是既有节点不移动规则的例外 |
| 异步任务成功、失败、重试或恢复 | 已有占位 | 原位置 | 不重新放置 | 同一节点 ID 和稳定占地 |
| 两名协作者同时选中同一空位 | 并发创建 | 服务端权威顺序 | 后提交的新节点或批次重新放置 | 不移动更早节点，不改变其他客户端视口 |
| 用户创建后主动拖动到重叠位置 | 手动布局 | 用户位置 | 不自动纠正 | 创建时避让不延伸为持续约束 |
| 打开已有重叠的旧画布 | 历史数据 | 原坐标 | 不处理 | 不自动迁移或整理 |

## 6. 目标模块与依赖方向

### 6.1 `node-geometry.js`

现有 `static/js/smart-canvas/node-geometry.js` 保留为节点几何的权威模块，并从当前主要支持单图片节点扩展为覆盖所有功能节点。

该模块负责：

- 根据节点数据计算稳定宽高和可见矩形。
- 计算普通功能节点的交互避让矩形。
- 为图片、视频、上传占位、Prompt、Splitter、Loop、Smart Group（编组）、Frame（分区）等提供确定性几何。
- 返回诊断信息，拒绝无效坐标或尺寸。
- 不生成候选位置，不选择方向，不修改画布状态。

手绘标注和画布文本可以继续拥有渲染所需几何，但 Node Placement 在构造障碍集合时必须排除它们。

### 6.2 新建 `node-placement.js`

新建 `static/js/smart-canvas/node-placement.js`，作为自动落位的深模块。它属于纯 in-process 计算，不引入网络、DOM、持久化或测试专用外部 seam。

建议只暴露一个主要接口：

```js
const plan = nodePlacement.plan({
    snapshot:{nodes},
    drafts:[draftNode],
    intent:{
        anchor:{
            kind:'point', // point | source | viewport
            x,
            y,
            sourceNodeId
        },
        relation:'downstream', // upstream | downstream | free
        arrangement:'single',  // single | horizontal-batch | vertical-batch | rigid
        frameId:''
    }
});
```

返回纯数据：

```js
{
    ok:true,
    placements:[{id:'node-1',x:1200,y:640}],
    bounds:{x:1200,y:640,width:316,height:180},
    diagnostics:[]
}
```

接口的具体字段可在实现时收窄，但调用方不得传入搜索轮数、候选列表、间距或碰撞策略。以下复杂度全部留在实现内部：

- 障碍集合规范化。
- 交互安全占地。
- 单节点、横向/纵向批次和刚性集合的整体边界。
- 点、来源和视口三类候选生成。
- 上游/下游方向。
- 分区同进同出。
- 硬约束过滤。
- 软对齐评分与确定性 tie-break。
- 可扩展搜索。
- 内部空间索引。

### 6.3 `canvas-mutation.js`

`static/js/smart-canvas/canvas-mutation.js` 继续负责创建事务和状态变更：

1. 构造尚未落位的节点草稿。
2. 调用 `nodePlacement.plan(...)`。
3. 原子写入节点、连接和最终位置。
4. 记录撤销信息。
5. 触发渲染和持久化。

普通自动创建调用方只能表达语义意图，不得自行搜索坐标。加载、重做、实时同步确认和历史恢复可以通过明确的 `restore/exact` 路径应用已持久化坐标；快速添加拖线可通过同一 Mutation seam 的 `exact` 模式应用用户刚刚指定的世界坐标。其他新建功能不得滥用该路径。

### 6.4 保留在原模块的职责

- `viewport-selection.js`：屏幕/世界坐标转换、视口平移、最小幅度 reveal。
- `canvas-interaction.js`：用户手动拖动和缩放。
- `smart-container.js`：编组内部自动排版、分区成员关系。
- 连接层：连接线绘制与路由。
- 浮层模块：菜单、工具栏、Popover 等 DOM 定位。

## 8. 分阶段迁移计划

### 阶段 0：建立特征测试与入口清单（已完成）

- 冻结当前正在进行的无关 Smart Canvas 改动，不覆盖现有 working tree。
- 列出所有创建功能节点的入口、创建类型、来源、是否有落点、是否为批次、是否位于容器。
- 为当前应保留的节点尺寸和创建事务建立特征测试。
- 对已知错误行为建立失败测试：固定位置重叠、搜索上限后重叠、批次被拆散、异步尺寸变化后重叠。

完成标准：每个迁移入口都有唯一清单项；后续不会因只搜索 `createImageNodeAt` 而漏掉 prepared node 或恢复路径。

### 阶段 1：深化 Node Geometry（已完成）

- 扩展 `node-geometry.js`，覆盖所有功能节点稳定几何。
- 增加交互避让矩形和方向性安全距离。
- 统一生成占位与最终节点尺寸计算。
- 让几何结果与 DOM 是否已渲染、节点是否在虚拟化视口内无关。

完成标准：Node Placement 所需的所有宽高都来自 Node Geometry，不读取 DOM，不在调用方重复尺寸常量。

### 阶段 2：实现纯 Node Placement 模块（已完成）

- 新建 `node-placement.js`。
- 实现 `single`、`horizontal-batch`、`vertical-batch`、`rigid` 四种集合语义。
- 实现三类锚点、方向优先级、分区规则、硬碰撞过滤、软对齐评分和确定性排序。
- 实现可扩展搜索；删除“搜索固定轮数后返回冲突首选点”的设计。
- 空间索引作为实现内部细节，不扩张公开接口。

完成标准：所有已确认规则都可通过 `plan(...)` 的纯输入/输出测试表达。

### 阶段 3：建立 Canvas Mutation seam（已完成）

- 让自动创建事务先构造草稿，再统一调用 Node Placement。
- 区分 `auto`、用户显式 `exact` 与 `restore/exact` 位置语义。
- 新建、连接、选择、撤销记录、渲染和保存保持一个事务。
- 阻止新业务调用方绕过放置模块直接提交自动坐标。

完成标准：至少一个端到端创建入口只传语义意图，不再计算坐标。

### 阶段 4：迁移生成链路（已完成）

按风险由低到高迁移：

1. 单个图片/视频 Pending Node。
2. 多结果批次。
3. Prompt Node 文字输出。
4. 反推提示词。
5. 智能抠图和其他生成模块。
6. Generation Recovery 缺失占位补建。

同时确保完成结果原位更新占位节点，删除 `generationOutputFindBatchPosition(...)`、`generationOutputNextPosition(...)` 和 `openNodePositionNear(...)` 的旧职责。

完成标准：成功、失败、重试、恢复和批次均保持稳定身份、稳定位置与稳定占地。

### 阶段 5：迁移直接创建、上传和集合操作（已完成）

- 画布创建菜单。
- 快速添加点击创建。
- 外部文件和资产拖放。
- 文件选择上传。
- 系统剪贴板粘贴。
- 画布节点复制/粘贴与 duplicate。
- 节点包导入。
- 图片工作台、扩图、拼图等输出。

完成标准：案例矩阵中所有非生成入口都经过同一放置模块；复制和导入只整体平移。

### 阶段 6：快速添加显式落点与视口 reveal（已完成）

- 拖线期间只保留指针引线，不渲染节点位置预览。
- 松手后通过 Mutation seam 的显式 `exact` 模式使用用户落点，不运行自动避让。
- 用户直接创建落在视口外时，由 Viewport Selection 执行最小平滑 reveal。
- 后台完成和协作者新增不触发 reveal。

完成标准：浏览器测试证明拖线落点不会被碰撞解析改变，且三类视口行为正确。

### 阶段 7：实时协作竞争处理（已完成）

- 服务端对新增功能节点或批次进行原子版本/占地校验。
- 较早确认的位置保持不变。
- 后提交创建基于最新画布快照重新计划，或收到明确冲突后由客户端重算并重试。
- 所有客户端最终收敛到相同持久化位置。
- Undo/Redo 恢复与并发占位冲突走同一规则。

完成标准：并发测试证明两个客户端不能持久化到同一合法槽位，且既有节点不移动。

### 阶段 8：删除旧逻辑与架构守卫（已完成）

- 删除迁移后无调用的旧放置函数和固定偏移。
- 将旧的浅模块测试替换为 Node Placement 接口测试；保留必要的集成和浏览器测试。
- 增加静态架构检查，禁止自动创建入口重新实现候选搜索或安全距离常量。
- 更新本文件的入口清单和完成状态。

完成标准：删除 `node-placement.js` 后，复杂度会重新散落到多个调用方；该模块通过“删除测试”，证明它提供了真实深度和 locality。
