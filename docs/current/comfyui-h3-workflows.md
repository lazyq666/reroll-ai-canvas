# ComfyUI H3 Composer 接入

状态：Current。跟踪：[LAZ-87](https://linear.app/lazyq/issue/LAZ-87)。

## 使用目标与范围

Administrator 在工作流设置中导入 API 格式的 H3 工作流。具备已识别 H3 两阶段结构的工作流以保存的名称出现在视频 Composer 的模型菜单“工作流”分组。用户选中后直接选择时长、分辨率、画幅，添加参考素材并提交，结果返回同一 Canvas。Workflow 仍是独立的执行选择，不注册为 API Model，也不修改 API Provider 的参数、Prompt 或参考素材规则。

视频结果节点在“生成引擎”中从 API 切回 ComfyUI 时，保留当前兼容的视频工作流选择；被旧设置覆盖时，恢复最近使用且仍可用的视频工作流及参数；历史选择缺失或已删除时，选择列表中可用的视频工作流。API 的历史设置携带的 ComfyUI 图片模式不能把有效的视频工作流切换强制退回 API。只有没有兼容视频工作流时，继续采用视频 API；空白或图片节点保留普通 ComfyUI 模式选择。此往返切换由 Composer 回归和真实页面验收覆盖。

本次适配的是研究中导出的 WORK-FISHER H3 两阶段模板：节点 7 / 14 为 H3 条件，13 为学习式放大，20 为音视频解码，21 为最终合成，11 为随机种子。识别同时核对两阶段采样、学习式放大、潜空间协调、最终解码的数据连接及共享随机种子；绕过任意阶段的图不启用 H3 能力。普通采样参数、模型选择和条件包装节点仍可修改。节点类型、位置或必要连接不符合此合同的工作流不启用 H3 能力，不按标题猜测。通用字段映射与普通工作流继续走原路径。设置页导入、命名与保存属于配置入口，生成验收入口为 Canvas Composer。

## 参数与素材合同

| 参数 | 提交范围 |
| --- | --- |
| 时长 | 4–15 秒的每个整数秒（共 12 档）；默认 4 秒 |
| 分辨率 | 512p、768p；默认 512p |
| 画幅 | 16:9、9:16、1:1；默认 16:9 |
| 512p 实际尺寸 | 横 896×512，竖 512×896，方 512×512 |
| 768p 实际尺寸 | 横 1344×768，竖 768×1344，方 768×768 |
| 参考素材 | 至少 1 项；最多 6 张图片、3 段视频、3 段音频，总计最多 12 项 |
| 视频/音频长度 | 单项 2–15 秒；视频总长与独立音频总长分别不超过 15 秒（服务端为文件时长舍入提供 50 毫秒容差） |
| 视频原声 | 按参考实例选择是否参与音频参考；启用但文件无音轨时拒绝提交 |

时长通过鼠标和键盘逐秒调整；保存与刷新恢复保留所选整数秒，既有 4/6/8/10 秒设置继续有效。服务端拒绝范围外、非整数类型、布尔值和空值。

只有省略参数时才采用默认值；显式传入空值、布尔值或未支持的枚举必须失败，不能静默切换到默认档位。

尺寸遵循模型要求的 32 倍数，横竖档位是名义画幅。内部按 17n+5 帧对齐生成，最终在 24fps 下裁切到所选时长，音频同步裁切；裁切后的两路内容通过 ComfyUI 原生 `CreateVideo → SaveVideo` 合并并完整写入末尾数据，交付 MP4 / H.264 / yuv420p 和 AAC 双声道音频。运行环境需要提供 `ImageFromBatch`、`AudioCrop`、`CreateVideo` 和 `SaveVideo` 原生节点；导入模板仍按节点 21 的 `VHS_VideoCombine` 结构识别，只有本次编译副本的输出尾端被替换。最终只回收节点 21，首阶段预览不作为成片交付。原生 `SaveVideo` 的元数据行为由远端 ComfyUI 的进程级设置控制：在本次验收环境默认会将编译后的工作流及 Prompt 写入 MP4 的 `prompt` 标签，导入模板中 VHS 的 `save_metadata=false` 不能控制这一原生节点；适配器不修改远端全局设置。

每次提交从模板副本编译，按实际素材创建加载节点，同时连接两个 H3 条件节点，移除无用分支和模板示例 Prompt / 图片。原模板不被运行改写。媒体引用基于稳定的 Reference Input Instance 和本次冻结顺序编译为 `<Picture N>`、`<Video N>`、`<Audio N>`；启用的视频原声音轨排在独立音频之前。语言切换只影响显示，不改变发送标签。删除、排序与重复 URL 的素材仍按各自实例处理；标签从 1 开始编号，缺失的引用编号在远端执行前拒绝。手写标签按已安装 T8 的语法接受大小写、空格、`Image` 别名及英文简写，例如 `<picture2>`、`<Image 2>`、`Picture#2`，统一为 `<Picture 2>` 后校验，不能被插件的旧单参考规则改指到另一张图。没有对应媒体类型时，未加尖括号的普通文字保持原文。

## 实例、上传与运行

设备的 ComfyUI 地址仍来自 Device State 中的 `COMFYUI_INSTANCES`，不写进 Workspace 工作流配置。H3 当前选择配置列表中的首个实例。`POST /api/upload?workflow_json=...` 仅向选定实例上传，并返回完整 `backend / name / subfolder / type`。提交快照必须包含同一已配置实例的上传身份；旧的无实例 `comfy_name` 缓存不能复用。运行 Reroll 的机器需要可执行的 `ffprobe`。视频与音频的真实时长由服务端 ffprobe 再次检查，无法检查时明确失败。对单项上限及各类型累计上限，15.05 秒以内按 15 秒接受，超过 15.05 秒拒绝；这只是容器时长舍入容差，不是额外的公开时长档位。T8 插件会把参考视频限制到本次生成帧数并向下对齐到 17n+5；允许上传 2–15 秒参考不等于模型会使用其每一帧。

`GET /api/workflows` 与单项工作流详情给出能力投影；Composer 按该投影呈现控件，服务端编译器再次校验。`POST /api/canvas-comfy-tasks` 接收独立 `workflow_inputs`，保持普通 API 图片/视频请求不变。已有 WorkflowRun、Generation Run、发布回执与 Target Guard 继续拥有任务和交付，不增加另一套任务生命周期。

提交 ComfyUI 前先建立 WebSocket，再用同一 client ID 提交。远端返回 prompt ID 后先持久化检查点，然后继续跟踪。事件按 prompt ID 过滤；公开进度仅包含阶段、步数、阶段百分比和队列前方任务数。排队、准备、第一阶段生成、放大、第二阶段生成、编码使用已有 Pending Node 呈现。百分比代表当前阶段，切换阶段时清空上阶段数值；重复进度不重复写盘，终态后的迟到事件不能恢复 Pending。

WebSocket 不可用或断开时以 queue/history 查询继续，刷新与服务端恢复都使用原 prompt ID、实例、client ID 和最终输出筛选规则，不重新提交。队列预算与运行预算分开；单次监控超时保留恢复资格，下一次仍查询同一远端任务；明确执行错误和没有最终输出会进入失败状态。ComfyUI 工作流只有在成片成为 Workspace 托管媒体后才交付成功；保存失败保留已完成的远端输出，只重试保存，不重新生成。Canvas 目标已删除或操作身份已变化时，仍由既有 Target Guard 决定交付，不能写入新目标。

## 验收与验证边界

代表性自动化入口：`tests/test_comfyui_h3.py`、`tests/test_comfyui_h3_boundaries.py`、`tests/test_comfyui_transport.py`、`tests/test_comfyui_api.py`、`tests/test_comfy_workflow_progress.py`、`tests/test_workflow_managed_delivery.py`，以及 `tests/comfy_h3_composer.test.cjs`、`tests/comfy_h3_settings_preview.test.cjs`、`tests/comfy_workflow_recovery.test.cjs` 和 `tests/composer_mixed_media_reference_test.cjs`。它们覆盖参数与素材边界、双阶段引用一致性、API 隔离、定向上传、最终输出筛选、阶段切换、检查点与保存重试。

实机验收使用 RTX 4080 / 16GB、研究导出的两阶段模板和 4 秒 / 512p / 16:9：单图与两图加视频原声、独立音频的混合参考均生成成功。Chrome 从设置页导入工作流，在模型菜单按名称选中，提交后显示阶段与步数，运行中刷新及切换语言仍接续原任务，最终在原 Canvas 播放 896×512、24fps、96 帧、4.000 秒的 H.264/AAC 成片。双角色 6 秒 / 512p 的横屏示例与最终竖屏原生保存复验均完成 Chrome 提交、第二阶段刷新恢复、原 Canvas 回填及播放；各自成片均为 144 帧，视频、音频和容器均为 6.000 秒，两个阶段使用同一 Prompt 与两张原始引用。刷新接续原 prompt ID，不增加远端任务。保存重试通过生产 Workspace 交付路径和自动化恢复回归验收。

页面验收还覆盖空白节点、缺少参考时的提交拦截、两张图片及视频/音频的本地引用、视频原声开关、稳定引用标记、中英文动态文案、明暗主题、鼠标参数选择与键盘时长调整。新建空白节点及空白节点切换工作流时，标题依据所选工作流的输出类型立即显示“视频生成”或“图片生成”；成片节点的默认标题和无障碍名称按实际媒体类型显示：视频、音频、图片或混合素材；自定义标题分支与素材别名不变。正在运行的节点沿用任务类型。参数弹层打开时，实际尺寸随画幅、分辨率立即刷新，保持当前弹层和焦点。H3 设置预览说明指向 Canvas 生成入口，普通工作流保留原有试跑入口。

扩展验收以两张不同角色图、固定种子和同一动作提示词模板，完成 4/6/8/10 秒 × 512p/768p × 三种画幅的全部 24 组真实成片。实际尺寸、24fps、96/144/192/240 帧、视频/音频/容器时长、双阶段引用及唯一最终输出均符合合同，全部文件通过完整音视频解码。矩阵保留修复前已合格的 14 个 VHS 成片，另有 10 个原生保存成片；原生输出尾端另有四种时长的独立检查，并由矩阵、素材测试和最终 Chrome 复验共同覆盖四种时长的完整 H3 生成。

4–15 秒扩展的自动化覆盖全部 12 时长 × 2 分辨率 × 3 画幅，共 72 个编译、保存及提交组合；范围外与非整数输入继续拒绝。独立 Chrome 15 秒 / 512p / 9:16 验收已完成双角色提交、第二阶段刷新接续同一任务、原 Canvas 回填和实际播放；成片为 512×896、24fps、360 帧，视频、音频和容器均为 15.000 秒。鼠标与键盘逐秒选择、15 秒设置恢复、中英文控件和明暗主题均经过实际页面检查。

新增 5/7/9/11/12/13/14/15 秒 × 六种尺寸预设的 48 组实机验证均已执行：38 组交付成功，10 组因显存不足未交付。成功成片全部使用原生保存，每组通过 22 项检查，包含准确尺寸、24fps、时长 × 24 帧、音视频及容器时长、双阶段 Prompt 与两张引用一致性、最终输出筛选和完整音视频解码；每个成功成片另审看五个均匀时间点的抽帧。连同此前 24 组，输出矩阵共 62/72 组有成功成片。

| 输出预设 | 本次固定条件下已通过的整数秒 | 未交付的整数秒 |
| --- | --- | --- |
| 512p，三种画幅 | 4–15 | 无 |
| 768p，1:1 | 4–15 | 无 |
| 768p，16:9 与 9:16 | 4–10 | 11–15，第二阶段显存不足 |

上述资源边界限定于本次 RTX 4080 / 16 GiB 设备、原两阶段模板、固定种子和两张角色图。十组失败均发生在第二阶段采样的 QKV / LoRA 计算；15 秒横屏在错误清理、队列空闲后重试仍失败，独立的工作流内存估算参数实验也未解决。诊断没有改动远端全局配置，诊断图不计入原模板矩阵。接口仍接受完整 4–15 秒范围；实际成片的尺寸与时长合同不保证每台设备都能完成所有组合。

补充 12 组正向素材测试全部生成并交付成功：结合主矩阵覆盖 1–6 张图片；覆盖纯视频原声开/关、纯音频、2 秒下限、15 秒单项上限、两视频与两独立音频混合，以及 6 图 + 3 视频 + 3 独立音频的 12 项上限。视频原声开启时的音频编号顺序也由实际双阶段连接核验。数量边界使用重复的图片、视频和音频实例验证；图片来自两个角色，不代表六个不同角色。素材边界与输出参数分别隔离验证，不代表所有素材文件或所有素材排列均与全部 72 个输出组合进行笛卡尔积实跑。

真实素材验证已覆盖无音轨视频启用原声、单项 16 秒视频/音频、两项各 8 秒视频/音频合计超限，均在 GPU 提交前拒绝；客户端谎报时长不能绕过服务端探测。

生成质量取决于模板、模型、素材与 Prompt；双角色实测中出现过裁切人物、背景人物被带入，以及提示词要求徒手但出现武器或武器中途消失，技术参数正确不等于构图、动作、物体连续性或角色保真度保证。当前支持的明确模板不代表任意 H3 图自动兼容。

研究阶段的设备、模型与模板依据见 [H3 接入研究](../archive/2026-10-14-comfyui-h3-integration-research.md)。
