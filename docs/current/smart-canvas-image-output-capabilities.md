# Smart Canvas 图片画幅与模型能力规格

> 状态：Current；已实施并通过相邻自动化与真实 Provider 能力验证
> 决策日期：2026-08-14
> 适用范围：Smart Canvas 的 Prompt Authoring、Generation Settings 与图片 Generation Run

## 实施阶段

1. **能力合同**：以 `resources/image-model-capabilities.json` 为人工确认配置入口，后端统一执行 maintained、discovered、fallback 的来源优先级，并提供单模型与多模型交集 API。
2. **Composer 与批量设置**：Smart Canvas 按当前能力渲染画幅和 Resolution Tier；单图自动画幅使用 `7%` 归一化，多图禁用自动，模型切换清除失效选择；批量生成只保留模型能力交集。
3. **Generation Output 物化**：保存 Provider Source Image 后读取真实尺寸；“自动”模式按当前唯一参考图的精确原始比例生成居中 `cover` 文件，明确画幅模式按用户选择的标准比例处理；画布、历史、下载和后续任务只引用 Materialized Output。
4. **历史分析与按需探测**：`scripts/analyze_image_capability_history.py` 先以零外部请求分析已有 Generation Run；仅对证据缺口使用 `scripts/probe_image_model_capabilities.py` 的 OpenAI-compatible 或 APIMART 模式，并逐任务记录远端 ID、下载真实图片、检查尺寸，输出可审计证据后再人工更新正式能力表。

2026-08-14 扩展画幅复核结果：即梦 5.0 的 `21:9 / 2K` 实际输出 `3024 × 1296`；APIMART GPT Image 2 的 `21:9 / 9:21 / 1K` 分别输出 `1915 × 821` 与 `821 × 1915`；APIMART Nano Banana 2 接受 `21:9`，但因网格对齐分别输出 `1584 × 672` 与 `3168 × 1344`，由 Materialized Output 轻裁为标准 `21:9`。Nano Banana 2 的 `9:21` 任务失败，因此不进入可选列表。

## 1. 背景

当前 Smart Canvas Composer 向不同图片模型展示近似统一的画幅与分辨率选项，且允许自定义比例和像素尺寸。不同供应商、模型版本和调用环境实际支持的范围并不一致；部分后端会改用最接近比例，部分会裁切，部分会把参数原样交给上游。因此，用户填写的画幅或尺寸可能与 Generation Output 不一致，界面也无法解释差异来自哪里。

本规格把“模型原生支持什么”“提交给供应商什么”和“产品最终向用户承诺什么”分开：后端统一描述模型能力，Composer 只展示当前选择可以兑现的选项。“自动”模式提交最接近的模型标准比例，但最终图片恢复当前参考图的精确原始比例；明确画幅模式则兑现用户选择的标准比例。

## 2. 产品保证

1. 用户只能选择当前模型或模型组合支持的画幅和 Resolution Tier。
2. “自动”表示跟随一张参考图，不表示让模型自由决定画幅。
3. “自动”模式的 Generation Output 必须恢复当前参考图的精确原始比例；明确画幅模式必须具有用户选择的标准画幅。两者都不得拉伸变形或增加留白。
4. 系统不提供自定义宽高比或精确像素尺寸，也不在导出阶段提供精确像素尺寸。
5. 模型切换、批量多模型和能力未知都有确定且可解释的降级规则。

## 3. 非目标

- 不承诺 `1K`、`2K`、`4K` 对应固定的像素宽高。
- 不提供逐模型单独配置批量任务参数的高级模式。
- 不要求所有供应商提供统一的在线能力发现 API。
- 不让用户在生成流程中手动调整裁切取景。
- 不把真实 API 能力探测放入每次提交都运行的常规 CI。

## 4. 核心术语

- **Image Model Capability**：一个精确模型版本支持的 Output Aspect Ratio、Resolution Tier 与可选输出能力（例如透明 PNG）。
- **Provider Request Aspect Ratio**：提交给供应商 API 的受支持标准比例，例如 `16:9`。
- **Output Aspect Ratio**：产品对最终图片承诺的宽高关系；“自动”模式为参考图精确原始比例，明确画幅模式为用户选择的标准比例。
- **Automatic Aspect Ratio**：由唯一一张参考图推导并归一化得到的 Provider Request Aspect Ratio，同时保留该参考图的精确原始比例用于最终物化。
- **Resolution Tier**：模型原生的清晰度档位，例如 `1K`、`2K`、`4K`，不是精确像素尺寸。
- **Provider Source Image**：供应商 API 返回、尚未经过产品画幅兑现处理的原始图片。
- **Materialized Output**：完成必要的 `cover` 处理后，实际保存并供画布、下载和后续任务使用的 Generation Output 文件。

## 5. 模型能力合同

### 5.1 单一来源

后端向前端返回统一的 Image Model Capability。前端不得再维护一份覆盖所有模型的固定画幅或清晰度数组，也不得根据模型名称猜测能力。

每条能力至少表达：

- 供应商与精确模型 ID；
- 支持的画幅列表；
- 支持的 Resolution Tier 列表；
- 默认 Resolution Tier；
- 能力来源；
- 最近确认时间。
- 是否支持透明 PNG 输出；未声明时必须按不支持处理。

“自动”是 Reroll 的产品行为，不是直接照搬供应商的 `auto` 参数，因此不作为一个普通模型画幅写入列表。

### 5.2 来源优先级

能力数据按以下顺序解析：

1. 项目内针对精确模型版本维护并已确认的配置；
2. API、CLI 或工作流能够稳定返回的结构化能力数据；
3. 能力未知时的通用兜底。

通用画幅兜底列表为：

`1:1、2:3、3:2、3:4、4:3、9:16、16:9`

能力未知时仍允许图片生成，但不展示未经确认的扩展比例，例如 `21:9`、`9:21`，也不展示自定义比例。为保证新模型接入后可以立即测试，Resolution Tier 暂时展示 `1K / 2K / 4K` 兼容选项；这些选项必须标记为未确认回退值，服务端不得将它们当成厂商已确认能力进行强校验。

### 5.3 数据获取边界

不同环境只能提供部分能力信息：

- 部分官方文档列出按模型区分的画幅与清晰度，但模型列表 API 未必返回这些字段；
- 部分 CLI 的帮助信息会列出选项，但不构成稳定的结构化运行时合同；
- RunningHub、ComfyUI 一类环境可暴露工作流字段选项，这代表工作流能力，不一定代表底层模型的完整能力；
- OpenAI-compatible 自定义服务可能接受、拒绝或忽略同一个尺寸参数。

因此，运行时发现只能作为能力来源之一，不能取代项目维护的统一能力合同。

## 6. Composer 交互规则

### 6.1 场景矩阵

| 场景 | 自动画幅 | 画幅选择 | 默认行为 |
|---|---|---|---|
| 文生图，无参考图 | 不提供 | 仅当前模型支持项 | 使用当前有效默认值 |
| 图生图，单张参考图且比例受支持 | 提供并默认选择 | 可改选支持项 | 显示“自动（已识别比例）” |
| 图生图，单张参考图但比例不受支持 | 不可用 | 必须选择支持项 | 生成前阻止并提示选择 |
| 图生图，两张及以上参考图 | 不可用 | 必须选择支持项 | 不以第一张图代替用户决策 |
| 多模型批量生成 | 条件提供 | 仅展示能力交集 | 所有结果使用同一设置 |

### 6.2 单图比例识别

系统读取当前参考图的真实宽高，并与当前模型支持的标准比例比较。相对偏差不超过 `7%` 时，归一化为误差最小的标准比例。例如 `405 × 240` 会归一为“自动（16:9）”。这里的 `16:9` 是 Provider Request Aspect Ratio；最终 Materialized Output 仍承诺 `405:240` 的精确原始比例。

若没有标准比例落入 `7%` 容差，输入图视为不符合当前模型画幅要求，“自动”不可用，用户必须从支持列表中选择。自动画幅必须每次从当前唯一参考图重新计算；之前参考图保存的识别结果不得替代当前尺寸、绕过无参考图或多参考图限制，也不得进入本次提交。

### 6.3 “自动”的执行含义

Composer 可以显示“自动”，但执行层应把已识别结果转换为明确标准画幅并提交给 API，同时冻结当前参考图的精确原始比例。例如界面显示“自动（16:9）”时，API 请求 `16:9`；若选择 `4K`，可请求 `3840 × 2160`。供应商结果返回后，再以冻结的参考图比例执行最终物化。

只有在供应商不支持明确比例，且已经确认其 `auto` 会跟随参考图时，适配器才可以向供应商提交 `auto`。不得把含义不确定的供应商 `auto` 直接暴露为产品承诺。

### 6.4 添加或删除参考图

- 一张参考图增加为两张时，若当前为“自动”，立即使该设置失效并要求用户选择画幅。
- 多张减少为一张时，只有该图比例受当前所有模型支持，才重新提供“自动”；不得自动覆盖用户已经选择的有效明确比例。
- 清空全部参考图后进入文生图规则。

### 6.5 切换模型

- 原画幅与 Resolution Tier 仍被新模型支持时，保留原选择。
- 任一设置不再受支持时，清除该失效项并就地提示“新模型不支持原设置，请重新选择”。
- 不把失效画幅静默替换为最接近比例。
- 单图图生图在参考图比例受新模型支持时，可以恢复“自动”；多图仍要求明确比例。

### 6.6 透明 PNG

- 只有精确模型能力显式声明 `supports_transparent_png: true` 时，Composer 才展示“透明 PNG”开关；未知模型和未声明模型不展示。
- 开关默认关闭。开启后，本次 Generation Run 冻结 `transparent_png: true`；后端必须再次按精确模型能力校验，不能信任前端或根据模型名猜测。
- APIMART 的 `gpt-image-2-official` 映射为 `background: "transparent"` 与 `output_format: "png"`；普通 `gpt-image-2` 路由没有这项能力。
- Codex 的 `gpt-image-2` 不依赖原生 `--background transparent`：文生图先调用 `images generate`，带参考图时先调用 `images edit`，两者都要求生成受控纯色底 PNG，再调用 `transparent extract --method chroma --matte-color auto --profile generic --strict` 本地提取 Alpha 并执行质量门。OpenAI-compatible CLI 路径才使用 `images generate/edit --background transparent --format png`。
- Composer 内布尔生成参数统一使用 `ic-switch` 的 Small 规格（`size="s"`，组件库变体名 `ic-switch-small`），标签字号使用 `var(--ui-font-size-2)`。

## 7. Resolution Tier

- 沿用现有 `1K / 2K / 4K` 档位式交互，但选项必须来自 Image Model Capability。
- 模型只支持部分档位时，只展示该部分。
- 模型只有一个已知档位时，隐藏控件并自动使用该档位。
- 能力未知时展示 `1K / 2K / 4K` 兼容测试选项，默认使用供应商默认值或 `1K`；待探测确认后替换为精确能力。
- 文生图和图生图都不提供自定义宽高、自定义比例或精确像素尺寸。
- 下载与导出也不增加精确像素尺寸输入。

## 8. 多模型批量生成

批量生成的画幅与 Resolution Tier 取所有已选模型能力列表的交集。每个模型使用同一套可见参数，不提供逐模型覆盖设置。

“自动”仅在以下条件全部满足时出现：

1. 恰好有一张参考图；
2. 该图可在 `7%` 容差内归一为一个标准比例；
3. 该标准比例被全部已选模型支持。

任一模型能力未知时，以通用画幅和 `1K / 2K / 4K` 兼容档位参与计算，但不把回退档位视为已确认能力。只有全部模型能力已确认且画幅或 Resolution Tier 没有交集时，才按能力冲突阻止生成并提示减少或重新选择模型组合。

## 9. 最终画幅兑现

后端在收到供应商结果后必须读取 Provider Source Image 的真实宽高，不能只信任请求参数或响应元数据。物化目标按以下优先级确定：

1. “自动”模式：使用本次请求中当前唯一参考图的精确原始比例；后端必须以同一请求携带的真实宽高复核，不接受不一致的旧值。
2. 明确画幅模式：使用提交给供应商的标准目标比例。

- 实际比例符合最终物化目标时，直接物化为 Generation Output。
- 实际比例不符合目标比例时，按 `cover` 规则处理：保持图片比例缩放以覆盖目标矩形，默认以中心为锚点，裁掉溢出部分。
- 禁止拉伸，禁止补白，不弹出手动取景界面。
- `cover` 只兑现目标比例，不承诺一个精确像素宽高。
- 处理后的图片必须保存为真实文件；画布预览、下载、历史记录和下游任务都引用该 Materialized Output。
- Provider Source Image 作为隐藏源文件保留，以便恢复、排查或未来重新处理。
- 若供应商已经返回正确比例，不重复裁切。
- 只有裁切或保存失败时才中断并提示用户，不把正常的供应商差异转化为额外选择。

## 10. 新模型能力探测脚本

### 10.1 运行方式

提供一个由开发者按需执行的脚本，使用真实凭证和真实 API 对指定供应商、模型、候选画幅与 Resolution Tier 发起生成。它用于接入新模型或复核模型升级，不进入常规 CI，也不自动修改线上配置。

脚本应支持通用候选集、扩展候选集和自定义候选文件，避免每次为供应商改脚本。真实调用会计费，运行前必须明确展示请求数量或要求显式确认。

### 10.2 记录字段

每次探测至少记录：

- 供应商、模型 ID 与调用环境；
- 请求画幅与 Resolution Tier；
- API 是否接受请求；
- 返回图片的真实宽高与计算所得比例；
- 比例相对偏差；
- API 是否替换或忽略参数；
- 尝试次数、耗时、测试时间和错误分类。

不得在报告或日志中写入 API Key、token 等秘密。

### 10.3 判定规则

- `supported`：请求成功，且实际输出与目标比例的相对偏差不超过 `1%`。
- `supported_with_materialization`：请求成功，相对偏差大于 `1%` 但不超过 `1.1%`，且现有居中 `cover` 物化可用极小裁切兑现标准比例。该放宽只用于供应商输出网格对齐，与参考图“自动”识别的 `7%` 门槛相互独立。
- `accepted_but_not_honored`：请求成功，但实际输出落在目标容差之外。
- `unsupported`：API 明确拒绝，或按配置重试后仍无法完成。
- 瞬时网络错误、限流和余额不足应单独标记为 `inconclusive`，不得误判为模型不支持。

只有 `supported` 和经人工复核的 `supported_with_materialization` 项可以进入用户可选列表。脚本输出机器可读报告和建议能力配置；开发者人工确认后再更新正式 Image Model Capability，脚本本身不得直接修改线上配置。

## 11. 验证要求

### 11.1 不调用真实 API 的常规测试

- 能力来源优先级与通用兜底正确。
- 单模型选项严格来自能力合同。
- 单图比例的 `7%` 归一化边界正确。
- 当前参考图会覆盖旧的自动画幅结果；尺寸未知、无参考图和多参考图不能借旧值启用“自动”或通过提交校验。
- “自动”模式同时冻结标准 Provider Request Aspect Ratio 与当前参考图精确比例；后端复核二者来源，并按后者物化最终输出。
- 多图禁用“自动”。
- 多模型正确计算画幅与 Resolution Tier 交集。
- 切换模型后保留有效项、清除失效项且不静默替换。
- 自定义比例、精确像素尺寸与自定义导出尺寸不再出现。
- 供应商结果比例不一致时，Materialized Output 经过居中 `cover` 且源图仍保留。
- 已按参考图比例裁切的自动模式结果不作为供应商画幅能力证据，避免历史分析把产品物化结果误判成 Provider 原始输出。
- 透明 PNG 开关只对已确认模型可见；提交参数经过前后端双重能力约束，APIMART HTTP 与 Codex CLI 使用各自的透明背景合同；Codex 文生图和参考图编辑都走受控底色加本地 Alpha 提取流水线，而不依赖不可靠的原生 Alpha。

### 11.2 按需真实 API 测试

- 探测脚本能下载结果并以文件真实尺寸判定，而不是只依据 HTTP 成功。
- 同一模型能产生可复核的 JSON 报告与建议能力配置。
- `accepted_but_not_honored` 不进入正式支持列表。
- 网格对齐导致的 `supported_with_materialization` 必须记录原始尺寸、误差和物化后尺寸。
- 限流、余额不足和网络故障不会被写成 `unsupported`。

## 12. 验收场景

1. 文生图选择一个模型时，只看到该模型支持的比例，没有“自动”和自定义尺寸。
2. 单图图生图上传 `405 × 240` 图片并选择 `4K` 时，即使旧设置保存过 `1:1`，仍默认显示“自动（16:9）”，向 API 提交 `16:9 / 3840 × 2160`；若供应商返回 `3840 × 2160`，系统按参考图的 `405:240` 精确比例居中裁为 `3645 × 2160` 后返回画布。
3. 单图上传 `21:2` 图片且模型不支持该比例时，生成按钮要求用户先选一个可用比例。
4. 第二张参考图加入后，“自动”失效且不能继续生成，直到用户选择明确比例。
5. 用户明确选择 `16:9`、API 却返回 `4:3` 时，系统自动生成居中 `cover` 的 `16:9` 真实文件，并保留 `4:3` 源图。
6. 模型从支持 `21:9` 的 A 切换到不支持该比例的 B 时，系统清除选择并提示，不替换成 `16:9`。
7. 批量选择模型 A 与 B 时，只展示二者共同支持的画幅和 Resolution Tier。
8. 新模型没有能力数据时，仍可使用通用画幅和供应商默认清晰度生成。
9. 探测脚本请求成功但返回错误比例时，报告为 `accepted_but_not_honored`，不会建议加入支持列表。
10. 选择 APIMART `gpt-image-2-official` 或 Codex `gpt-image-2` 时出现“透明 PNG”小号开关；开启后分别提交官方 HTTP 参数或 CLI 参数。切换到普通 APIMART `gpt-image-2` 时开关消失且请求不携带透明输出设置。
