# Smart Matting 性能与容量

> Status: Current  
> Last verified: 2026-08-28  
> Tracked work: GitHub Issue #89

## 当前合同

- Smart Matting 使用有界 FIFO 队列和可配置 Worker 池；默认同时处理 2 个任务。
- Worker 共享一个 BiRefNet ONNX Session，模型只加载一份。ONNX 前景预测可以并行。
- Alpha 精修使用 `pymatting` 的 Numba 运行时。默认 Numba workqueue 不支持多个 Python
  线程同时进入，因此精修阶段必须串行；否则并行 2 即可能让进程直接终止。
- 每个任务写入独立临时 PNG，完整保存后再原子替换目标文件。相同来源同时提交时不会让
  其他请求读到半写入文件。
- 并行数只改变同时执行量，不改变权限、每用户活动任务限制、FIFO 排队、缓存键、结果
  URL 或浏览器轮询合同。

这里的“并行 2”可以理解为两个抠图工位共享一台 Alpha 精修设备：一个任务精修时，另一
个任务仍可做 ONNX 前景预测。它不是让全部计算步骤无条件同时执行。

## 标准容量测试

管理员可以双击 `admin-tools/抠图并行容量测试-macOS.command`，或在终端运行：

```bash
.venv/bin/python scripts/performance/run_matting_capacity.py
```

默认协议固定为：

1. 生成一张确定性的 2048×1536 RGB 场景图，记录 SHA-256；也可用 `--input` 指定图片。
2. 先完成一次不计入结果的模型加载和预热。
3. 依次测试并行 1、2、3、4；每档至少处理 4 个独立产物。
4. 每个产物都重新执行完整抠图，并校验为尺寸一致的 RGBA PNG，不复用应用层结果缓存。
5. 记录成功率、批次耗时、单任务 P50/P95、吞吐、进程 CPU 和峰值 RSS。

若某档出现任务失败，或峰值 RSS 已超过物理内存 85%，runner 会停止测试更高档位，避免
为了寻找理论上限继续扩大设备风险。

报告默认写入 `/private/tmp/ic-matting-capacity/<时间>/report.json` 与 `report.md`。一次报告
是当前设备当时状态的执行证据，不会自动成为其他设备的容量承诺。

### 判定 Gate

“最高稳定测试档位”要求：零失败、峰值 RSS 不超过物理内存 85%，且单任务 P95 不超过
串行基线 3 倍。“建议日常并行数”还要求：峰值 RSS 不超过 75%，P95 不超过基线 2.5
倍，并且相对上一建议档位至少再提高 10% 吞吐。较低档位未通过时，不越级推荐更高档位。

最高稳定档位回答“本次固定场景测到了哪里仍未越过稳定 Gate”；建议值回答“长期日常使用
应配置多少”。两者不能互换，也都不是无限时长压力测试的证明。

## 2026-08-28 本机结果

设备为 `Mac16,11`、12 个逻辑核心、48GB 物理内存；BiRefNet General 模型；标准输入
2048×1536；每档 4 个任务。预热约 18.8 秒，不计入各档结果。

| 并行数 | 成功/总数 | P50 | P95 | 吞吐（任务/分钟） | 峰值 RSS |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 4/4 | 7,186 ms | 8,548 ms | 8.10 | 10,571 MB |
| 2 | 4/4 | 9,284 ms | 10,278 ms | 12.16 | 15,294 MB |
| 3 | 4/4 | 18,759 ms | 19,468 ms | 9.06 | 15,637 MB |
| 4 | 4/4 | 22,227 ms | 22,931 ms | 10.47 | 17,070 MB |

结论：本次最高稳定测试档位为 4，建议日常并行数为 2。并行 2 相对串行把吞吐提高约
50%，而并行 3、4 出现资源争用，吞吐低于并行 2，单任务等待也明显增加。因此应用默认
值从 1 调整为 2；4 只表示本次短场景测到的最高稳定档位。

峰值 RSS 是进程启动后的高水位，包含共享模型，并会保留前一档已经申请的内存；它适合
做安全水位判断，不应被解释为某一任务独占的内存。

## 配置与运维

以下变量在 `.env` 中配置，修改后必须重启服务：

| 变量 | 默认值 | 有效范围 / 含义 |
| --- | ---: | --- |
| `MATTING_MAX_CONCURRENCY` | 2 | 1–8；同时运行的 Worker 数。超过 4 尚未在当前设备验证 |
| `MATTING_QUEUE_MAX` | 24 | 1–100；等待队列的有界容量 |
| `MATTING_PER_USER_MAX` | 3 | 1–10；单用户 queued + running 任务上限 |
| `MATTING_CPU_THREADS` | 2 | 1–8；每次 ONNX 推理的 CPU 线程数 |
| `MATTING_REFINE_MAX_PIXELS` | 1,500,000 | Alpha 精修工作图像素上限 |
| `MATTING_MAX_SOURCE_PIXELS` | 40,000,000 | 单张来源图像素上限 |

不要只因为更高档位“没有报错”就上调生产值。输入尺寸、同时运行的其他 Provider、散热、
剩余内存和长时间负载都会改变结果。配置上调前应在目标设备重跑标准测试；若输出失败、
系统换页明显或同机其他功能延迟恶化，应回退到上一通过档位并重启服务。
