# Suno 音乐实验室

- Status: Current
- Verified: 2026-10-15
- Tracking: [LAZ-85](https://linear.app/lazyq/issue/LAZ-85)

## 目标与范围

在首页「画布 / 在线生成 / 实验室」中选择实验室，点击 SUNO 图片卡片进入工作台。
入口仅显示提供的品牌图片，按原始比例适配至最大 410px 宽，不叠加标题、说明、按钮或波形图标；整张卡片作为链接，支持键盘聚焦和 Enter 进入，并提供中英文辅助名称。
用户可以通过文字生成音乐，或选择/拖入 1–4 首本地参考音频创作，试听结果、查看自己在当前 Workspace 的记录，
并保存已有音频或准备 MP3、M4A、WAV 文件。三个当前版本为 `v6`、`v6-wild`、`v6-mini`；
旧版已被 APIMart 下线，不作为可提交选项。

当前实现不提供音频训练、自定义训练模型、续写、伴奏/人声分离、Persona 创建、画布音频生成节点，
也不把音频导入误作为普通 generation 的参考音频参数。已有 Persona ID 可在文字创作和 Cover 改编中使用。

添加参考后明确选择参考方式，默认 **改编 Cover**，通过 uploadCover 按原曲旋律改编，可独立选择人声歌曲或纯音乐。
**灵感 Inspire** 通过 inspo 借鉴风格、节奏或配器创作新曲，不承诺保留原旋律；最多四首参考。
选择纯音乐且仍选 Inspire 时保留草稿并阻止提交，提示切换 Cover，不偷换操作或忽略纯音乐要求。
参考方式不随音乐类型改变。历史与“沿用设置”保留实际操作；旧 inspo 记录明确标为灵感创作。
页面提供本地选择、拖入、试听和移除，不要求填写 URL。旧 uploadTask 路由保留兼容和既有历史。
Cover 与 Inspire 不承诺和 Suno 官网在不同模型、参数下产生相同结果。续写 uploadExtend 未接入。

### 本地参考音频

- 支持 MP3、WAV、M4A、AAC、OGG、FLAC，1–4 首、每首最多 50 MiB（界面简写 50 MB）。
  文件类型与大小是本应用保护边界；APIMart 未公布 inspo 的具体文件大小和时长上限，不套用翻唱的 8 分钟限制。
- Cover 改编只接受一首不足 480 秒的音频。服务端通过项目既有 ffprobe 能力读取实际时长；不可读取、缺少 ffprobe 或超长时在创建 Run、托管和收费提交之前拒绝。该时长是应用依据英文文档采取的保守限制；中文文档表述为建议不超过 8 分钟，没有付费验证恰好 480 秒的上游行为。多参考切换 Cover 时保留全部文件并提示移除多余参考，禁用生成，不静默挑选第一首。
- 选择/拖入只创建浏览器本地预览，不上传、不计费。超过数量、空文件、类型不支持或过大时整批拒绝，保留已有选择；移除释放本地预览引用。
- 点击生成时，multipart 文件先进入当前 Workspace 的 `assets/input/imported/` Managed Media，
  使用内容摘要去重。服务端核对扩展名、容器头和实际读取大小；不会将任意本机路径或调用方 URL 当作参考。
- Run 先持久保存原始参考的工作区相对引用、文件名和大小，再在后台使用项目现有 Litterbox 临时托管，
  失败或回读校验失败时尝试用户授权的 tmpfiles.org（固定六小时存储）。音乐不再使用只提供 POST 下载的 temp.sh。
  参考卡片不再常驻显示大小与临时托管说明；大小和格式限制保留在添加音频弹窗中。Litterbox 沿用已有 `LITTERBOX_UPLOAD_URL`、`LITTERBOX_TIME` 配置；
  tmpfiles 的上传响应是文件页面，服务端从该页面读取实际签名下载地址。签名有效期短于文件六小时存储期，
  因此每次提交前现取现验，不在历史中缓存复用。上游延迟读取导致签名失效仍可能失败；不会自动重复收费重提。
  不新增公开配置项或公开本机服务。
  外部托管只收到音频文件，不附带 APIMart 密钥。参考 URL 只用于当前上游提交，不作为历史音频的权威。
  上传返回成功还不够：收费提交前使用不带凭据的 GET 回读，核对完整字节数和 SHA-256；网页、截断或损坏文件均视为托管失败。重定向有界并逐跳检查公网 URL，读取不超过本地文件大小。
- 历史参考通过所属 Run 的鉴权路由试听；“沿用设置”带回参考和参数，可移除或补充文件。
  再次生成从本地副本重新托管，不依赖已过期的公网链接。刷新未提交的草稿会丢失本次选择，已提交的参考保留。
- 参考权重控制整体影响，不承诺相似度百分比。支持的文件实际能否解码/生成仍取决于浏览器和上游。

## 布局设计记录

正式页采用已确认的 Suno Create 布局：保留首页侧栏，左侧创作、右侧「我的工作区」、底部统一播放器。原[布局研究](../archive/2026-10-14-suno-create-layout-prototype.md)保留为设计记录。独立 Demo 仍可用 `npm run prototype:music-create` 运行，使用示例音频和模拟生成，不调用正式音乐 API；正式入口为 `/?page=music`。

## 用户与权限

Administrator 和 Designer 可以使用；Guest Account 与未登录访客不能调用音乐 API。
使用已有 API 平台配置中的 APIMart 平台与密钥；不新增音乐密钥设置或环境变量。
平台禁用、密钥缺失时不出现在可用列表；没有平台时禁用提交并提示配置。
音乐历史、任务详情、参考试听/复用、继续查询和音频下载都校验当前账号；其他账号的 Run 返回 404。
这里的个人历史是界面/API 的账号筛选，底层 Managed Media 沿用可信小团队 Workspace 的共享内容边界。

## 参数与组件

所有产品文案从共享 i18n 提供中英文。控件使用公共 `ic-*` 和 `--ui-*`，沿用首页主题与语言。
桌面创作区与曲库独立滚动，生成按钮固定在表单底部，播放器横跨内容区底部。
默认详细模式显示内容、风格和折叠的「更多设置」；简单模式只收起风格与高级设置，不清空草稿、修改参数或切换旧 custom=false 协议。
参考音频、已有 Persona ID、Inspire 位于输入上方；Persona 可在独立弹窗或高级设置内填写，两处共享同一草稿；内容支持扩大编辑。参考入口先打开文件选择说明弹窗，也接受在创作区直接拖入。
左栏使用 400px 标准桌面宽度（宽屏 438px，较窄桌面 370px / 335px），标题栏高 61px；三个添加入口等宽排列。内容卡片先显示动态标题，再在同一行显示歌词来源下拉与纯音乐开关；输入区使用公共 `ic-textarea appearance="plain"`，由卡片提供背景，避免叠加输入框边界。风格卡片显示字数与添加风格按钮；重复点同一风格不重复添加，快捷添加遵守 1000 Unicode 字符限制。示例轮换三段描述，只改文字，不切换纯音乐或歌词来源。
高级设置按标签/控件横排和完整宽度滑块组织；歌名使用公共 `ic-input` 默认表面外观（浅色主题白底，深色主题跟随公共表面色），与服务平台保持紧凑。底部清空草稿与生成按钮同排，费用提示始终可见。清空会移除本地参考选择并恢复默认创作参数（含 v6、自动写词与关闭可选权重），保留当前服务平台、已生成历史与结果播放，不删除服务端媒体。
添加参考后显示紧凑虚线卡片：顶部为 Cover / Inspire Large 分段选择器与方式说明，文件行依次为播放/暂停、单行文件名、时长和移除图标，底部仅保留参考数量与添加音频；移除大块上传占位和重复标题。默认 Cover；主动点击 Inspire 入口则选择 Inspire。卡片仍接受拖入；超过 Cover 数量时保留文件并显示原校验。未支持的参数保留并禁用。
内容区不足 700px 时通过 49px 高的下划线单选导航切换「创作音乐 / 我的工作区」，保留 48px 创作标题栏；歌曲操作改为有可访问名称的图标，避免英文标签挤高网格卡片。生成按钮和播放器仍可达。
模型选择器使用公共 `ic-select` 的 Small 次级变体。模式切换、搜索、生成、筛选与风格标签使用公共 `shape="pill"`；生成按钮高 45px、搜索高 37px、筛选高 30px、风格标签高 28px。高级滑块始终显示百分比，禁用时保留数值；时长只显示一份行标签，数字框通过 `label-hidden` 保留可访问名称。
右侧遵循 Create Demo 的紧凑歌曲列表：标题栏之后，搜索、排序、列表/网格图标在同一工具栏；全部、本次生成与禁用的收藏入口在下一行，之后直接显示歌曲；不显示“最近生成 / 可试听”分组行和“已加载 X 首”计数，也不展示收藏与跨全部历史最早排序的常驻说明。
成功歌曲逐首呈现 80px 封面、歌名与模型/操作、风格、收藏/沿用/下载和最右侧详情按钮，不再重复显示任务标题、完成徽标或组尾操作。播放入口位于封面内，悬停、键盘聚焦或播放时显示；触屏保持可见。窄屏允许工具栏换行并缩小封面。
列表与网格中的歌名、描述及首个操作图标保持同一视觉左边线，图标保留完整点击区域。歌名（含未填写标题时回退的生成描述）在可用文字列内单行省略，不覆盖封面、模型/状态与右侧操作；悬停标题可读完整文本，键盘和点击仍可打开详情。长中文、含空格英文与无空格长词在窄屏和语言切换后遵守同一限制。
待处理、失败或尚无曲目的记录与普通歌曲复用同一列表行和网格卡片，不再使用整行边框的任务卡。桌面封面位为 80px 正方形（窄屏 64px，网格随卡片等比缩放）：排队/处理中显示公共 `ic-generation-pending kind="image"`，通过公开的 Base / Badge Part 适配方形缩略图，状态文字位于歌曲信息区；失败封面以 Prompt Generation Node 的失败样式为参考，使用 Error 图标与失败文字，右侧描述展示具体原因，长文可在详情中完整读取。保留沿用设置、歌曲名与右侧详情入口；未完成记录不提供播放/下载。状态轮询未变化时复用动画实例，失败或完成后移除动画；完成后按真实输出曲数替换待处理行。取消、停止等终态显示真实状态，不继续播放生成动画。可恢复异常仍在详情中继续原任务，格式准备记录归入对应歌曲。
参考、Persona、展开编辑、单曲详情和格式下载使用 520px 宽的公共 compact 弹窗，在窄屏缩到视口内；快速打开后按 Escape 也能正常关闭。
明确的 localhost `?prototype=music&variant=B` 仍是历史评审演示，不提交收费请求。

新文字创作统一提交 custom=true；纯音乐关闭自动写词，不提交人声选择。后台仍兼容旧 custom=false 记录；沿用旧简单记录时将描述作为自动写词主题带回。人声值为 `Male/Female`；
变化程度为 `off/normal/high/extra/max`；格式为 `mp3/m4a/wav`。
Inspire 使用独立合同：风格为 tags，新奇程度为 weirdness；歌词/主题均可留空，自动写词可切换。
不提交 custom、instrumental、persona_id、duration、gpt_description；时长、人设控件仍可见但禁用；保留歌名、风格、排除风格、权重、人声、变化程度、Max 与格式。
纯音乐参考改编使用 custom=true、instrumental=true；将描述与风格用逗号空格合并为 tags（最多 1000 Unicode 字符），省略歌词 prompt、auto_lyrics、人声字段。新奇程度映射为 weirdness，目标时长映射为 duration_s；支持既有 Persona、Max、格式和权重。原始描述与风格分别保存在 Run 参数中，沿用时完整恢复。超长在前后端拒绝，不截断草稿。
人声 Cover 同样 custom=true，但 instrumental=false，prompt 保留为歌词或自动改写的输入，style 单独映射 tags，不把歌词合并进风格。保留 auto_lyrics 与可选 vocal_gender。
普通生成仍使用 style 和 weirdness_constraint，不因切换参考模式泄漏不支持的参数。

中文名称采用 2–4 字，描述不超过 20 字；品牌、单位、编号和用户内容单独展示。英文使用对应自然短句。删除重复宣传语和版本退役常驻说明；费用说明常驻，用户能在提交前看到。

## 交互与状态

1. 进入工作台读取可用平台与当前账号历史；无记录时展示空状态。读取配置失败时禁用生成；配置与历史分别恢复，成功加载其中一项不会清除另一项仍存在的故障。
2. 输入内容并提交。先进行本地和服务端参数校验，再创建后台 Generation Run。
   提交期间表单不可更改，提交动作禁用；接收后清除搜索与会话筛选、曲库回到顶部，立即在右侧显示运行记录；窄屏切到「我的工作区」，不用等待生成结束。
3. 后端持续查询远端任务；浏览器每 5 秒刷新历史，切页或关闭浏览器不取消后台运行。
4. 曲库按时间倒序逐首显示成功歌曲；数据仍保留所属生成记录，点击歌名或右侧详情只查看该首歌曲。支持列表/网格、全部/本次生成筛选，按单首歌曲搜索已加载的歌名、描述和风格，无结果时可一键清除筛选。收藏、收藏筛选及跨全部历史的最早排序继续禁用；不可用原因由收藏控件提示与排序选项标签表达。格式导出归入来源曲目，避免被误认成新作品。
   “音乐详情”以该曲大封面、标题、描述/歌词与冻结参数摘要为主体，完整参数、任务编号、实际 Credits 和来源参考收在折叠区域。等待/失败等任务记录继续展示原任务详情及恢复入口。曲目和详情中的试听控制同一个底部播放器，支持播放、暂停、进度、音量、上下首与单曲循环；播放队列取当前搜索/筛选内已加载的曲目，手动上下首在当前已加载队列内循环，自动播完到队尾停止；不请求未加载曲目。空闲状态点击播放从当前队列第一首开始。
   底部播放器固定高 82px：左侧封面/文件名和来源，中间循环/上下首/播放控制，下方为当前时间、进度条、总时长，右侧静音与音量；窄屏收起音量、循环和当前时间，保留主播放与进度。进度和音量使用公共 `ic-slider appearance="media"`，隐藏可见表单标签但保留中英文可访问名称、数值与键盘操作。静音保留音量，调整音量恢复声音。
   创作卡片中的参考试听与结果歌曲共用同一个底部音频元素；上下首按当前来源在参考列表或结果队列内切换。移除正在试听的参考或清空参考草稿时停止并释放该播放源；移除其他参考保持当前试听。参考与结果播放互斥。普通轮询、模式/语言/列表网格切换和打开详情不会替换底部音频元素或打断播放。
   任务和音频编号收在折叠的“完整生成参数”内；开关值显示开启/关闭，历史协议的创作模式显示简单模式/详细模式。
5. 点击歌曲“下载”先查看格式弹窗；可用格式读取已保存文件，不创建上游收费任务。
   “准备格式”创建独立格式任务，费用提示常驻；准备中、成功与失败在对应格式行回读，失败可重试。网络、权限或下载错误显示在当前弹窗内，不被浮层遮住。
6. “沿用设置”只填回草稿，不自动生成；参考记录同时带回原始音频，关闭详情并返回创作页，用户可修改后再次提交。

错误与需要处理的提醒使用右上角公共 `ic-alert` 队列（Danger / Warning），可关闭、不占表单布局、不抢焦点；
详情操作的错误留在活动 `ic-dialog` 内同样的反馈区。使用公共队列处理堆叠与离场动效，页面只负责位置。
相同首屏服务故障不因配置、历史两个请求重复弹出。关闭后不会因轮询或语言切换重新出现；再次主动操作仍失败时可重新提示。
已提交、沿用设置等完成反馈使用公共底部 `ic-toast`，避让生成操作栏。

「本次生成」只包含当前页面会话中提交成功的记录；刷新后清空该筛选集合，历史记录仍保留。

失败记录的右侧「⋯」提供「音乐详情 / 删除记录」。删除使用公共 `ic-menu` 与
`ic-dialog`：明确对象、永久删除记录内容和未使用本地文件的后果，保留取消及 Escape。
确认期间禁用重复提交、取消和关闭；异常显示在弹窗内，可切换语言和重试。
删除成功后立即移除记录，刷新/重启不再出现，较早发出的轮询响应不能将其恢复。
当前草稿中沿用该记录的参考会同时移除；其他歌曲的播放保持连续。

删除仅限本人已经结束的失败记录。服务端先排空 HTTP/Realtime 工作并检查活动生成，
只回收该记录关联、且无其他持久引用或会话使用保护的本地文件。共享、恢复副本引用、
本次服务期间创建或读取的文件仍保留，并在完成提示中说明；后续可通过管理员手动清理回收。
不删除外部原文件、远端资源或不属于本记录的孤立文件。文件检查失败时不删除；
部分文件删除失败时保留记录供重试，已经删除的文件不恢复。文件处理成功后清除
JSON/SQLite 中的提示词、参数、错误、参考、远端编号和结果，仅留不含用户内容的
最小操作回执，防止旧请求再次收费。本人重复删除幂等成功，其他账号返回 404。
云端工作区暂不支持此操作。详见 [ADR-0019](../adr/0019-failed-music-record-erasure.md)。

历史倒序排列，每页 30 条；“加载更多”使用稳定时间/ID 游标。语言切换同时更新动态记录、错误、
按钮及参数；用户输入和历史里的歌曲内容不翻译。按钮、单选、表单与 details 支持键盘操作。

## 失败与恢复

- 首屏配置/历史接口未注册（无业务错误码的 404）：提示“音乐服务未就绪，请重启 Reroll 后重试”，不误报为网络故障或暗示已提交生成。更新页面后仍运行旧后台时，需要通过受控重启加载当前代码。
- 本地登录失效（401）、账号无权限（403）分别提示重新登录或无权限；已有供应商业务错误码继续按其含义显示，不把密钥拒绝混同为本地账号权限。
- 配置或历史读取失败使用加载失败提示；Alert 的“重试”只重新读取配置和历史，绝不提交生成/导出。恢复后清除对应加载错误，保留表单与已有曲目；后台轮询失败不反复弹出提醒。
- 参数不合法：区分未填写与超长，分别指出描述/歌词/主题、歌名、风格或时长问题；提示后聚焦可编辑字段，不联系收费接口，保留草稿。
- 本地参考保存失败：不启动生成；托管失败：Run 显示“尚未提交生成”，可沿用设置后重试。托管中断且未获得远端编号时保守终止，不自动重发收费请求。
- 平台明确返回内容审核未通过时显示对应双语提示，不把它伪装成参考成功，也不自动改写或重提。未给具体原因时不推断为版权、人声或某一词语。
- 密钥拒绝、余额不足、限流、任务缺失或上游失败：显示可理解的中英文错误，不泄漏上游原始响应或密钥。
- 已有 task ID 的查询网络故障、临时 5xx、限流与暂时无法解析的结果：保留任务并继续查询，绝不重新生成。
- POST 超时或丢失任务编号：标记“提交结果未知”，不自动重发；用户应先在 APIMart 控制台核对。
- 生成文件保存失败：记录保持可恢复，重查原任务并重试保存；不重新付费提交。
- 历史加载失败：保留已有列表，曲库持续显示失败状态；该状态支持语言切换，不因切换视图或搜索被清除，成功刷新后恢复。
- 付费导出：同账号、同来源记录、同曲目、相同格式集合只创建一次任务。格式次序或重复值不影响复用；
  刷新、服务重启仍复用记录。不同格式集合属于新任务，按上游规则收费。
- 终态失败不提供无效的“继续查询”。有效的可恢复异常可以重试原任务；无自动取消或自动再生成。

## 逐曲封面

- 上游 `result.music[]` 每项的 `image_url` 和 `image_large_url` 对应同项音频，解析时保持逐曲归属，不从任务级字段推断。
- 两个字段只接受通过既有公网 URL 校验的地址；缺失、无效、带凭据或本地地址的封面被忽略，不丢弃可播放音频。
- 成功结果保存时将封面导入现有 Managed Media，Run 结果保存本地 `/assets/` 引用；同一结果中的相同图片地址只保存一次。历史和重启恢复读取同一结果，不建立封面数据库。
- 封面保存是可选步骤：图片服务失败时保留已校验远端地址，音频仍按原合同成功保存。前端使用无 Referer 的图片请求；列表和播放器优先小图，详情优先大图，加载失败尝试另一尺寸后显示音乐图标。
- 旧记录和未返回封面的记录直接显示占位图，仍可试听、下载、沿用设置；不自动重新付费生成，也不凭空为旧历史补图。

## API 与存储责任

`backend/infinite_canvas/music_lab.py` 拥有参数、APIMart 音乐客户端、执行器和专用路由，
`main.py` 只注入现有账号、Provider 凭据、GenerationRuns、Managed Media 导入与文件下载能力。

| 应用 API | 行为 |
| --- | --- |
| `GET /api/music/config` | 可用平台、版本和格式，不返回密钥 |
| `POST /api/music/generations` | 平台、operation_id、settings，202 返回 Run |
| `POST /api/music/inspirations` | multipart：payload JSON 含平台、operation_id、settings、references（1–4 个）；files 最多 4 个。新文件以 file_index 引用，已有参考以所属 run_id/index 引用；202 返回 Run |
| `POST /api/music/covers` | multipart 结构同 inspirations，但恰好 1 个参考；人声或纯音乐自定义参数；先校验实际时长，再创建 suno-cover Run，202 返回 Run |
| `GET /api/music/runs/{id}/references/{index}` | 原始参考试听，零起始 index；校验所属账号 |
| `POST /api/music/uploads` | 兼容保留：平台、operation_id、公网 audio_url，202 返回 Run；页面无此入口 |
| `GET /api/music/history?limit=&cursor=` | 当前账号的音乐 Run，limit 1–100 |
| `GET /api/music/runs/{id}` | 账号隔离的详情 |
| `DELETE /api/music/runs/{id}` | 本人失败记录内容与可回收本地文件删除；返回 `deleted`, `file_count`, `total_bytes`, `retained_count` |
| `POST /api/music/runs/{id}/resume` | 恢复原任务查询 |
| `POST /api/music/runs/{id}/downloads` | audio_index 从 1 开始，formats 数组，202 返回格式任务 |
| `GET /api/music/runs/{id}/audio/{index}?download=true` | 文件下载；index 从 0 开始；省略 download 则用于试听 |

上游为 `POST /v1/music/generations`、`POST /v1/music/generations/uploadTask`、
`POST /v1/music/generations/inspo`、`POST /v1/music/generations/uploadCover`、`POST /v1/music/generations/download` 以及 `GET /v1/music/tasks/{id}`。
旧 `/wav` 接口不使用。没有任务编号时不自动重试收费 POST。

Generation Run 继续使用当前 Workspace 的 SQLite 权威或既有 legacy JSON 模式；不增加第二套历史库。
保存请求参数、参考的相对路径/名称/大小、状态、远端编号和结果；凭据只在执行时读取。全部音频保存到现有 Managed Media；
仅有 audio_id 的上传结果不伪造链接。历史直接筛选 owner 与 surface=suno 的 Run，不发布 Global History，
不写 Canvas。现有媒体清理扫描 Run 请求、公开元数据和结果中的引用；提交前的导入同样使用既有会话保护租约。移除草稿中的参考不主动删除工作区文件。恢复、输出与边界详见[生成链路](generation-pipeline.md)。
