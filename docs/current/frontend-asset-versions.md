## 用户行为

升级后，正常打开或刷新页面即可加载与当前代码一致的资源，无须清除浏览器缓存。内容指纹是文件内容的稳定标识；内容或依赖变化会生成新的 `?v=asset-…` 地址。未受影响的资源地址保持不变。

HTML 页面要求重新验证缓存；带内容指纹的静态资源允许长期缓存。启动、页面请求和发布检查均不改写源码。长期打开的旧标签页不会被强制刷新；工作中的安全升级提示另行设计。

本机制不改变媒体命名规则，不重命名历史结果或磁盘文件。生成结果继续遵守[媒体命名合同](../active/2026-09-20-smart-canvas-media-naming.md)。

## 唯一生成入口

完成内容修改后，在仓库根目录执行：

```bash
python3.12 scripts/sync_frontend_assets.py
python3.12 scripts/sync_frontend_assets.py --check
```

第一个命令同步引用、生成清单和兼容标记。第二个命令只读检查，发现过期版本、缺失文件、新增或移除资源未同步时返回失败，并指出资源、引用位置和修复命令。路径或排除规则错误时，生成命令也会停止，避免写入半份结果。

`static/frontend-assets.json` 记录资源和直接依赖。每次运行重新盘点 `static/` 下的 JavaScript、CSS、HTML、JSON，并沿资源引用发现图片、字体等文件；未被任何页面引用的新业务脚本也必须进入清单。清单由生成命令维护，不能手工填入版本来绕过检查。

## 引用与依赖

- 页面标签、内联脚本、静态模块导入与再导出、字面量 `import()`、`new Worker(new URL(...))`、CSS `@import` / `url()`、动态加载器中的完整 URL 列表使用同一机制。
- 使用 `/static/…`、`./…`、`../…` 等完整字面量 URL；HTML、CSS 和 `new URL()` 也支持不带 `./` 的相对文件名。新增加载方式必须扩展发现规则并加入回归，不能拼接业务脚本目录与文件名。检查会拒绝计算型模块、Worker 和不完整的 `/static/js/`、`/static/css/` URL。
- 子资源变化先更新其引用方，再向页面传递。无环依赖使用最终文件字节的 SHA-256 前 12 位；循环依赖将环内版本归一化后按路径排序计算，因此一次运行收敛。时间、机器路径和文件 mtime 不参与指纹。
- i18n 加载器直接持有每个翻译脚本的完整版本地址。头像 PNG 集合的动态文件名使用统一生成器计算的集合指纹；头像清单与调用脚本仍进入普通依赖图。
- Infinite Canvas UI 的 `VERSION` 保留为 `core.js` 指纹的兼容标记，各模块使用自己的内容指纹。原 UI、头像同步脚本均委托统一入口，不再维护独立规则。发布 `VERSION` 与更新说明仍按原规则递增，但不覆盖资源指纹或分享页引用。
- Node 的 `require()` 是本地文件读取路径，不加浏览器查询参数。测试页面和浏览器脚本中已有版本的绝对资源 URL 随生成器更新，但测试内容不参与产品指纹。

## 排除与缓存边界

[策略文件](../../scripts/frontend-assets-policy.json)明确列出固定第三方快照、Node 专用校验器和非产品原型目录，并记录原因。第三方目录有 SHA-256 内容锁，文件新增、删除或修改都会使检查失败；升级第三方快照时需要核对来源和许可证并显式更新内容锁。Web Awesome 还保留原始包的独立完整性校验。业务资源引用被排除的非产品文件时失败。

外部 URL、用户媒体与 API 返回的内容不属于此源码资源图。固定第三方地址及未加指纹的静态请求要求重新验证；这不关闭带指纹资源的缓存。普通页面及启动、恢复、搬迁页面返回 `Cache-Control: no-cache`；`FrontendStaticFiles` 对 `asset-…` 地址返回长期缓存策略，条件请求仍可返回 304。已有页面导航参数不参与代码版本计算。

## 验收与发布

[生成器回归](../../tests/test_frontend_assets.py)覆盖独立模块变更、间接依赖、循环依赖、缺失文件、新文件、排除项内容锁、只读失败、重复执行和 HTTP 缓存策略。

[真实浏览器升级回归](../../tests/frontend_cache_upgrade_browser.cjs)使用[临时服务](../../tests/frontend_upgrade_fixture.py)执行两个对照：

1. 先加载旧版并生成一次，建立真实缓存，确认旧版采用服务商长名称。
2. 在同一浏览器、同一标签页保留缓存，切换新版并普通刷新。负对照保留旧地址，验证旧代码仍从缓存执行且保存长名称；正对照更新指纹，验证结果为 `image-01.png`。
3. 正对照检查自动保存、真实 WebSocket 的第二标签页同步、手动重命名、结果重放与重新打开，并切换中英文。另以受控子模块、动态导入、Worker、CSS 依赖验证传播，用浏览器网络事件确认未变脚本确实复用缓存。

测试使用生产静态服务、前端生成完成路径和后端 Canvas Mutation 规则，模型任务由固定结果夹具替代，画布落在临时目录。不使用真实账号、用户画布或付费模型；不清缓存、不禁用缓存、不在升级中替换浏览器。

安装锁定依赖与 Chromium 后运行：

```bash
ASSET_TEST_PYTHON=.venv/bin/python node tests/frontend_cache_upgrade_browser.cjs
```

[Public readiness](public-readiness.md)的仓库合同组执行统一只读检查，必需浏览器组执行缓存升级回归。合并后的 main 检查与生效规则回读仍是发布完成条件，本地通过不替代这些条件。
