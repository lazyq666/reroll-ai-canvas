# API Settings Package

> Status: Current  
> Last verified: 2026-09-07
> File extension: `.icapi`; encrypted envelope v1, settings content v2; imports v1 and v2

API Settings Package 在可用模型管理页顶部的「API 与模型备份」中统一导出和导入，用于备份及跨设备、跨环境迁移。只有 Administrator 可以使用。它不替代 Workspace 内容或账号备份。

## 设置页职责与简化规则

API 设置管理平台连接、凭据及模型清单；可用模型管理显示名称、显隐、顺序及模型详情。备份入口只在可用模型管理页提供一组导入／导出动作；API 设置页不再提供备份按钮或弹窗。

- 模型拉取成功直接打开选择器。「选择模型」可以再次打开本次已拉取的清单，避免重复请求；手动添加仍用于上游未列出的模型。
- 选择器只显示模型、Model ID 和类型三列；移除根据名字猜测的系列字母。分类标签保留「已选数／总数」，不再重复提供底部数量汇总。搜索及分类切换保留选择，取消不应用清单；打开时切换语言，表格、计数和空状态一起更新。
- 可用模型表只显示名称、Model ID、Provider ID、显隐和操作五列。图标与已确认的功能标签放在名称栏；没有功能标签时不显示占位符。图标仍帮助识别模型，功能标签仍来自正式能力目录。
- 拖动与上下移动按钮都保留，按钮支持键盘排序。不同 Provider 的同名模型仍是独立条目，不能为减少列数而丢失路由身份。
- 密码框由同一份导入／导出状态生成文案及校验，不接受会被覆盖的标题／描述参数。关闭等待、预览确认、错误反馈、自动保存和编辑期间的同步保护属于实际恢复路径，不能作为冗余删除。

### API 连接检测

「检测地址」执行期间，按钮保持 Loading 并禁止重复检测；不使用会自动消失的 Toast 表示
检测进度。成功或失败结果通过当前平台设置中的 `ic-alert` 保留，直到用户关闭、再次检测、
修改连接或切换平台。切换语言会更新说明；HTTP 错误保留状态码与平台返回的原因，网络
无响应不能显示为 HTTP 0。检测期间修改连接或切换平台后，旧响应不能更新新平台的设置或反馈。

检测结果只确认对应检查接口（HTTP 平台通常为模型列表接口）是否可用，不保证某个模型的
生成权限。Key 已保存、连接检测通过和生成任务成功是三个不同的事实。

连接设置没有变化时，检测成功不重新保存全部平台配置；检测确实改变协议或接口类型时仍
自动保存。保存通知携带来源标识，设置页忽略自己的通知及主页面转发的同源通知；父页面
和顶层页面为同一窗口时只通知一次，避免重复加载盖过检测结果。

验收：`node tests/api_settings_connection_feedback_browser_smoke.cjs` 覆盖一次检测、重复点击、
持久成功与失败结果、重试、HTTP 与网络错误、关闭、中英文切换、键盘、明暗主题和过期响应。

## 人工测试

使用测试安装或测试平台；真实备份往返应在两个隔离安装中验证，因为仅切换 Workspace 不隔离 API 密钥和安装级模型能力。

1. **选择模型**：拉取模型，搜索一个已选模型并取消勾选，再清空搜索。分类计数应减少，其他选择保留；先取消弹窗确认清单不变，再重新打开、修改并应用。手动添加一个测试 Model ID，切页及刷新后仍存在。
2. **名称保存**：先打开 API 设置，再到可用模型给测试模型改名为「测试模型 A」，移开焦点；回到早先打开的 API 设置修改平台名称，再回模型页并刷新。显示名称仍为「测试模型 A」，Model ID 和 Provider ID 不变。
3. **同步移除**：保持模型页已打开，在 API 页移除该测试模型；返回模型页，不点浏览器刷新。模型行及分类数量应自动更新。另一浏览器标签页也应更新。
4. **显隐与排序**：连续隐藏两个模型，再恢复其中一个；用拖动和上下箭头各调整一次顺序。刷新后状态一致；隐藏模型仍在管理员列表中，生成选择器中不显示。
5. **模型详情**：打开测试模型详情，修改一个能力，先取消确认未生效，再保存并应用。重新打开仍是保存值；有拆分图层或透明 PNG 能力时，名称下显示相应标签。无标签的模型不出现多余占位。
6. **备份往返**：进入可用模型管理页顶部的「API 与模型备份」；在源安装配置名称、顺序、显隐和能力，导出加密包。目标测试安装先用错误密码导入，确认配置未变；用正确密码预览后取消，确认仍未变；再次导入并确认，逐项比较上述设置。CLI 在目标设备重新登录。旧版包仍能导入，预览明确显示旧版范围。
7. **布局与恢复**：选择器、备份弹窗打开时切换中文／英文及明／暗主题；数量、表头和提示应同步翻译，选中状态保留。用 Tab、空格／Enter 完成勾选和操作，再缩窄窗口确认按钮可达。浏览器开发者工具切为离线后尝试保存，应提示失败并保留编辑；恢复网络后再次保存成功。

## 消融复验

运行 `node tests/settings_ablation_test.cjs`。它只在子进程内替换读取的脚本文本，不改源码或真实配置：简化版应输出两项 `PASS`；删除跨页通知、未保存编辑保护、弹窗关闭等待三项试验应输出 `KEEP`，表示已有验收成功发现退化，正式版本保留这些保护。

备份页面回归运行 `node tests/model_settings_backup_browser_smoke.cjs`；它覆盖导出前保存、密码校验、文件下载、预览取消、错误密码、导入后清单与能力更新和保存失败阻止导出。其他页面回归运行 `node tests/api_settings_jimeng_model_delete_browser_smoke.cjs` 与 `node tests/model_capability_workbench_browser_smoke.cjs`；使用合成配置及隔离服务，不调用真实 Provider。这些脚本默认使用 macOS Chrome，可分别用 `API_SETTINGS_BROWSER`、`IC_BROWSER_BIN` 指定本机浏览器路径。完整备份的真实存储往返由 `.venv/bin/python -m unittest tests.test_complete_api_settings_backup` 验证。

## 名称的保存

当前 Workspace 的 `data/api_providers.json` 中，每个平台的 `model_names` 保存「Model ID → 显示名称」。稳定身份仍是 Provider ID 与 Model ID；改名不改变请求路由。同一个模型在不同 Provider 下可以有不同显示名称。

「可用模型」拥有名称编辑。API 设置页保存连接或重新选择模型时，服务端保留现存名称，只从提交内容补充尚无名称的 ID，防止早先打开的页面将新名称覆盖为旧名称或 Model ID。暂时移出清单的名称保留，重新加入相同 ID 时可以恢复。备份导入属于显式恢复操作，允许覆盖包内平台的名称。

模型排序与显隐保存在同一工作区的 `data/available_models.json`；管理员维护的能力详情保存在安装级 `model-capability-workbench.json`。这三个位置通过同一个备份入口收集。

显示名称只负责展示，包含“价格”等备注不应阻止能力详情保存。复验时可将 APIMART 的 `gpt-image-2-official` 命名为「GPT Image 2 - 官方渠道（4 倍价格）」，在详情勾选 `5:4`、`4:5`、`3:1`、`1:3` 并保存；弹窗应关闭，重新打开和刷新页面后仍保留勾选。若请求失败，错误应显示在弹窗底部，保留编辑并允许重试。

模型能力保存不再检查费用关键词或字段名片段；显示名称、资料文字、版本号中的 `fee` 及字段名 `feedback` 均不能因此被拒绝。名称不进入能力保存请求，保存按稳定 Model ID 定位，只读取一次当前模型清单，不重建整张详情表。旧客户端携带的名称字段会被忽略。此边界由 `tests/test_model_capability_workbench.py`、`tests/test_model_capabilities.py` 与 `tests/test_model_capability_matrix.py` 覆盖，包含共享模型跨平台保存及重新读取。

### 模型详情保存的消融复验

运行 `.venv/bin/python tests/model_capability_ablation.py`。脚本在隔离子进程内替换方法，不改源码或真实配置；默认版本应输出 `PASS`，四项保护被临时移除后应输出 `KEEP`，说明验收发现了退化。

| 实验 | 结果与决定 |
| --- | --- |
| 删除资料文字关键词拦截 | 69 项既有回归通过，自由文本原样保存；删除 |
| 删除字段名中的费用片段扫描 | `feedback` 保存与目录重读由失败变为通过；加入状态回归后共 71 项通过；删除 |
| 删除未使用的名称参数及保存前整表重建 | 71 项保存、目录、API 与完整备份回归通过；删除，保留一次当前清单读取 |
| 临时移除上下限校验 | 最小值大于最大值的草稿被接受，验收失败；保留 |
| 临时移除目录支持状态校验 | 无效状态替换原目录，验收失败；保留 |
| 临时移除发布失败回滚 | 激活失败后仍残留发布数据，验收失败；保留 |
| 临时移除管理员检查 | 非管理员不再被拒绝，验收失败；保留 |

人工复验：重启后台并刷新页面，编辑 `gpt-image-2` 的参考图数量、输出数量和画幅后保存，再打开确认；随后导出加密备份，在隔离测试环境导入并确认相同设置。保存失败时仍在弹窗中显示提示、保留编辑；恢复后可重试。

API 设置保存模型清单，或可用模型管理页导入备份后，已打开的可用模型页通过页面通知和跨标签页通知重新读取最新清单；返回浏览器页面也会重试同步，无需手动刷新。页面有未保存的名称、显隐或排序时先保留编辑，保存结束后同步；迟到的旧响应不能覆盖新编辑或恢复已移除的条目。保存期间已从 API 清单移除的模型以服务端清单为准，不保留幽灵行。

## 导出范围

- API 平台的名称、连接地址、连接类型、启用／首选状态、模型清单、模型显示名称、模型协议、工作流配置和现有 API 密钥。
- CLI 平台的共享模型设置；不包含 CLI 可执行文件路径、连接、登录状态或 Session。目标设备须安装 CLI 并重新登录。
- 所有配置模型的分类、排序和显隐，包括停用平台及隐藏模型。
- 图片、视频和文字模型的能力合同，包括图片编辑与图层拆分。保存当前基线与已发布配置；已配置上限不会因源设备的运行限制而被截短。目标设备仍执行自己的运行上限。
- RunningHub 用户工作流和相应凭据。未发布能力草稿、审核历史、Account、其他 Instance State、Workspace 媒体、其他设备设置及缓存不进入包。

导出或导入前等待当前模型页待保存设置完成；保存失败时不下载旧状态。密码至少 8 个字符，最长 256 个字符，不写入包。包沿用 scrypt 与 AES-256-GCM 认证加密，单包最大 16 MiB，超限在下载前失败。

## 导入与冲突

流程为：选文件 → 输入密码 → 解密并完整校验 → 显示平台名称、新增／更新平台数、模型条目数和覆盖范围 → 确认 → 原子合并。

- 预览只校验，不应用包内设置；取消或关闭弹窗不导入。
- 按稳定 Provider ID 更新或新增，不按显示名称合并。包内平台的模型配置覆盖目标同 ID 平台，其他平台保留。
- 相同 Provider ID 的连接类型不同，整个导入拒绝；先调整冲突 ID 后重试。不会把本机 CLI 身份静默转换成 API 平台。
- 包内非空 API 密钥替换对应密钥；没有携带的密钥不清空目标值。CLI 凭据不导入、不清空。
- 包内排序和显隐优先恢复，目标其他平台的模型追加在后，保留其显隐。包内首选平台优先，保证最多一个首选。
- 能力按 Provider ID、Model ID 和 Operation 校验并一次发布，记录备份恢复操作；目标其他模型的能力与历史保留。
- 完整性校验包括模型清单、名称映射、排序／显隐、能力身份及合同。密码错误、损坏、不支持的版本、冲突或非法内容均不写入。
- 导入失败回滚平台、连接、密钥文件及进程环境、工作流、排序／显隐和能力文件；重新激活回滚后的目录。写入期间与其他配置及能力编辑互斥，不留下半套设置。
- 导入不切换 Workspace，不更改账号、权限或 CLI 登录状态。成功反馈仅显示平台名称及计数，不回显密钥。导入后自动重新读取模型清单及能力详情，更新功能标签，并通知其他已打开页面；没有待保存编辑的 API 页同步平台配置。

旧版 v1 内容继续使用原先的非 CLI 平台合并规则，不恢复 CLI 配置、能力详情或源端显隐；确认弹窗明确提示旧版范围。新导出使用 v2 内容，但保持 v1 加密封装。旧应用会拒绝 v2 内容，须更新后再导入，避免旧应用静默丢弃新增字段。

- `tests/available_model_management_sync_test.cjs`：变更通知、跨标签页、待保存编辑、并发移除、迟到响应和失败重试；`tests/model_settings_sync_browser_harness.html` 在两个持续打开的实际设置页验证删除后列表和计数同步。

- `tests/api_settings_backup_state_test.cjs`：密码表单关闭后再进入下一步，提交与取消都清理密码。
- `tests/test_complete_api_settings_backup.py`：真实存储适配器跨环境往返、停用与隐藏模型、CLI 模型、能力详情、预览无写入、旧包兼容、非法内容与启用失败回滚。

- 实际可用模型管理页检查中文／英文、Light／Dark、默认／密码弹窗／预览／取消／错误与成功反馈、Pointer／Keyboard；测试使用隔离服务和合成配置，不请求真实 Provider。
