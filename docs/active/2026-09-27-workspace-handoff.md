# OneDrive 轮流编辑：工作区安全交接

- Status: Implemented locally; real two-device OneDrive acceptance pending
- Feature: F03
- Tracked by: [LAZ-69](https://linear.app/lazyq/issue/LAZ-69)
- Decision: [ADR-0017](../adr/0017-offline-workspace-handoff.md)

可选[在线交接扩展](2026-09-29-online-workspace-handoff.md)仅替代已配对 Workspace 的手动编号验收；本文继续定义离线模式及共享停写校验边界。

## 目标与边界

两台可信设备轮流编辑同一 Workspace，继续使用本地 SQLite 的读写速度。
首次成功执行“安全关闭并交接”才启用保护。现有未启用工作区的启动行为不变；
只支持已正式迁移的本地 SQLite authority，JSON 兼容和 Turso 模式不执行本流程。
这里的唯一性是指定完整版本的交接，不是合并画布、生成任务和批次的三库。

OneDrive 云端确认不在本版本中。必须在两台设备使用同版本应用，等待上传和下载
完成，并由使用者独立传递上一台成功交接的编号。不能用同步目录中自己读到的编号
证明它是最新的。两端同写、绕过新版客户端，以及首次启用标记尚未到达的全旧副本
不能靠本地文件校验解决。本功能不修复既有丢失节点，也不自动合并冲突。

## 使用流程、权限与界面

1. 本机 Administrator 从“数据存储位置”进入“安全关闭并交接”。外层工作台会对
   同源 Canvas iframe 调用正式 `preparePageRefresh`，保存提示词与分层草稿并等待
   Canvas acknowledgement；离线、上传、生成或保存不确定时保留当前页面。
2. `/workspace-handoff` 说明整个工作区停止写入的后果。确认时若仍有 Canvas 连接，
   要求先保存并关闭其他标签页；活动 Run、批量任务及待发布结果也阻止交接。
3. 服务进入维护，拒绝新业务请求，排空已接纳的 HTTP 请求（包括可能写入的 GET），
   关闭并排空 WebSocket，停止后台工作。停写之后失败则保留维护状态与占用，允许重试；
   停写之前的阻塞允许继续使用工作区。后台已经关闭时不能因重试重复启动或写入。
4. 检查点、完整性、外键、身份、待交付记录和全量文件校验成功后，发布交接记录，
   释放占用。页面显示交接编号和“本机已准备好”，提供复制，刷新页面仍可读取成功结果。
5. 下一次启动先进入验收；Local Operator 输入上一台提供的编号，完整校验通过后
   才进入受控重启和正常 Store 初始化。界面不预填同步目录中的编号。

### 冲突详情与显式隔离

恢复页列出当前主记录和具体冲突路径、字节数、修改时间、可展开的 SHA-256，以及
记录副本是否与主记录内容相同。修改时间不用于推荐最新版本，页面不从副本中建议编号。
检测范围包括控制目录的 handoff 副本/遗留临时文件，以及 data/assets 中未知数据库副本。
可在页面直接切换中英文和明暗主题，重新检查会清除上次处理确认。
文案使用短句，操作先于细节。文件大小、修改时间、摘要及备份路径按需展开；冲突时隐藏
交接前的准备说明。相同副本不重复展示零差异统计，不同副本仍直接展示节点差异。
确认区保持可见的备份、独有内容不合并和跨设备同步删除说明，勾选确认与执行按钮分开。

关闭交接失败也直接显示冲突列表，不依赖进入启动恢复状态。此时仅本机管理员可以读取
当前运行工作区的文件详情；具体失败码在刷新后保留，继续拒绝业务写入。后台全部停止且
本机仍持有原占用时，另提供“备份并删除”操作：保留当前数据库，清理所选副本后自动重试交接。

关闭阶段的数据库副本按正式文件名对应到当前使用的数据库；页面直接标明保留路径，
不再将尚未生成的 handoff.json 显示为待保留主记录。仅字节摘要完全相同、数据库可读且
没有非空 WAL/journal 的副本默认勾选。不同副本不默认选中；Canvas 数据库显示含回收站的
画布/节点数量、两侧独有节点数、同 ID 内容/顺序变化数和前 20 个受影响画布名称。
这些摘要不覆盖全部历史与任务，不用修改时间、条目数量或局部差异宣称哪份较新。
用户可明确选择不同的副本，但必须确认保留当前文件、独有内容不合并和同步删除的后果。

删除前验证原安装 active 回执；尚未首次交接、无记录且无回执的原工作区也可处理。
封存、外来 active、回执不匹配均不能借此绕过验收。所有当前数据库与所选副本先完整
备份、fsync 并核对摘要；列表变化、非空日志、非法路径或备份失败阻止删除。
只移除服务端列表中允许选择的副本，不接受主数据库路径或任意客户端路径。
页面断连和正常停服会等待后台处理，不提前释放占用。完成后页面重试交接；若仍有其他
冲突或重新同步送达的副本，继续阻止交接并保留备份位置。此流程不替换主数据库或合并节点。

启动恢复阶段，Local Operator 先暂停两端 OneDrive，同步完成的编号仍须从上一台独立取得。勾选确认
保留当前 `handoff.json` 后，可执行“备份冲突副本并打开”：它只接受已封存且与编号和
完整数据相符的主记录，并要求列出的冲突均为可读取的 handoff 记录。数据库副本、符号
链接、未完成交接或无法核实的主记录不提供自动处理，不选择替代数据库或合并节点。

处理沿用占用 OS 锁和原占用记录检查；列表摘要过期、编号错误、数据变化都拒绝继续。
备份位于 Device State 的 `workspace-handoff/<identity-sha256>/conflicts/<operation-id>/`，
包含主记录、冲突原始字节及列表信息。每份冲突先改名为仍可被检测的暂存文件，备份
校验并持久化后才移出工作区；失败时备份与未处理/暂存文件均保留，允许重新检查。
同步程序在原路径重新送达的文件不会被删除。隔离后仍经过完整启动验收，成功才重启。
页面明确说明：恢复 OneDrive 后，冲突文件的移除会传播到其他设备；本机备份不随工作区同步。

关闭普通浏览器标签、关闭终端、强制退出或断电不自动声称交接成功。启用后的 active
状态保留，原安装可持匹配本机回执恢复，再显式交接；另一台不能超时接管。
同一台正常重新打开 sealed 工作区也需输入编号，避免自动接受自洽旧副本。
语言切换重绘动态状态，中英文提供相同操作；使用共享 ic-card / ic-button /
ic-form-field / ic-input，支持 Light/Dark、Pointer 和 Keyboard。

## 持久化与恢复

- Workspace `.infinite-canvas-service/handoff.json`：版本、Workspace identity、交接编号、
  父编号、sealed/active、服务身份、活动 session，以及路径对应的 SHA-256 和字节数。
- Device State `workspace-handoff/<identity-sha256>/receipt.json`：本机接受的版本与 session。
  activating/active 回执使接受过程的中断可以在原安装恢复；已消费的旧 seal 不可回放。
- 同目录 `backups/<handoff-id>/`：停写、检查点之后的非 assets 文件与 manifest，一一校验。
  备份保留，不自动轮转或删除；媒体本身不复制到 Device State，恢复整工作区仍需要原媒体。
- 清单覆盖 `data/` 和 `assets/` 的现存文件及工作区 identity；排除 `data/recovery/`、
  `data/update_backups/` 和系统缩略图元数据。此清单证明已存在文件的交接一致性，
  不宣称修复交接前就已经缺失的外部引用或素材。
- SQLite 主文件包含 WAL 已提交内容后才进入清单；非空 WAL/journal、检查点 busy、
  未识别数据库副本、符号链接、未知 schema/身份、物理损坏、文件变化一律拒绝。
  SHM 为暂态索引，不参与摘要；不主动删除任何数据库 sidecar。
- 备份和双次源摘要检查完成后原子发布 manifest。OneDrive 不保证跨文件到达顺序，
  所以接收端始终验证完整清单，不能只看标记文件的存在。
- 冲突时原文件、冲突文件与历史备份均保留。恢复采用经核对的完整来源，不能挑一个
  修改时间较新的 SQLite 覆盖。丢失编号时可在原设备本机 backup manifest 中核对成功
  交接记录；不得从未确认的新设备同步副本猜测最新版本。

完整性检查与全量摘要是显式交接成本，素材很多时会耗时；不在每次节点保存时执行。

## HTTP 和代码责任

- `GET /workspace-handoff`：无内容数据的静态页面；运行时 shell 在维护和恢复时继续提供。
- `GET /api/runtime/handoff`：本机管理员读取关闭状态和编号；恢复阶段只返回原因码，不泄露候选编号。
- `POST /api/runtime/handoff`：本机管理员、同源，幂等交接；页面断连不会取消已经开始的后台交接。
- `POST /api/runtime/handoff/conflicts`：本机管理员、同源，仅就绪或交接失败阶段，读取当前运行
  工作区的冲突详情；不缓存，停写且持有原占用时提供对比与可删除建议。
- `POST /api/runtime/handoff/conflicts/cleanup`：本机管理员、同源，仅交接失败阶段；要求列表摘要、
  显式选择的路径与确认，串行备份删除；保持停写，成功不等于交接完成。
- `POST /api/runtime/recovery/handoff`：仅本机恢复阶段、同源，接受 `handoff_id`，校验后受控重启。
- `POST /api/runtime/recovery/handoff/conflicts`：本机、同源、仅恢复阶段，返回只读冲突列表与摘要；不缓存。
  验收请求可显式携带 `conflict_snapshot`，在 OS 锁内校验、备份隔离，再执行正常启动验收。
- `workspace_handoff.py`：一致性快照、清单、回执、备份与验收。
- `WorkspaceService.acquire_occupation`：取得 OS 锁后、占用发布及任何 Store 写入前执行验收。
- `ApplicationRuntime` / `RuntimeGateway`：冻结、HTTP/WS 排空、失败停写和重试。
- `main.py` / `LegacyInitializer`：现有后台服务的关闭与释放组合，不另建业务存储。
