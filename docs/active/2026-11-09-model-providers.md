## 设计转译

采用「供应商 → 该供应商的连接与模型」作为主层级。首页回答“我接入了哪些供应商”；详情回答“这家供应商连接什么服务、提供哪些模型”。

保留 Reroll 的图像、视频、文本分类及原生组件、字体与明暗主题。采用 achromatic-ledger 的中性列表方向（seed 1292658405），识别依靠供应商图标、真实名称和模型 ID；不增加统计卡、费用、路由分组或订阅管理。

Reroll 的公共 Dialog 合同禁止叠加弹窗。供应商详情使用独立页面区域和返回按钮。初版将模型选择与手动添加放在弹窗；2026-11-09 用户要求参考 Magpie 改为同页完成，现将两者移入详情模型区，仅能力详情与必要的后果确认继续使用单层弹窗。

现有配置继续自动保存，并显示简短保存状态；返回前等待未完成保存，失败留在详情。添加供应商时选择预设即创建配置，并进入详情填写密钥；自定义供应商允许先保存空连接。这与 Magpie 的提交式添加不同，属于本次实现方案，待用户评审。

## 合并后的行为

- 全局设置只保留「模型供应商」入口和一个 iframe；旧模型管理地址跳转到合并页，旧导航记忆映射到新入口。
- 首页提供搜索、启用开关、添加供应商；导入、导出收进一个「备份」菜单。
- 添加目录包括现有可支持的 API 服务、本机 CLI 和自定义连接，不声称支持 Magpie 的全部协议或供应商。
- 详情中连接设置和模型表共用供应商上下文。已有密钥的 API 连接默认收起；首次接入和本机工具连接展开。密钥已保存不表示已连通，更不表示已验证生成。
- 模型区使用「已添加 / 供应商列表」两个页内视图。供应商列表首次进入时获取模型，以可勾选的标签呈现；提供名称／ID 搜索、类型筛选、全选／全不选及「显示其余 N 个」，默认最多显示 12 个。批量操作作用于当前搜索与类型筛选的全部匹配项，包括尚未展开的项；已添加模型只读标记，不纳入新增计数。切换视图保留本次勾选与已获取结果，切换供应商或返回供应商首页则清空。点击「添加所选模型」才保存，并回到已添加列表；失败保留选择和就地错误，可直接重试。
- 手动添加从模型区右上角在页内展开，填写 ID、类型与可选显示名称；取消不保存，失败保留输入。缺少密钥时仍可直接手动记录模型；供应商发现必须先满足连接配置要求。添加与手动输入均不打开 Dialog、不创建遮罩、不锁定整页滚动。
- 模型行以显示名称为主，名称与 ID 不同时在下方显示 ID；点击名称或菜单「重命名」才进入编辑。显示开关保留，模型设置、上移、下移和移除收入「更多」。手动添加填写 ID、类型和可选显示名称；「本地命名」的功能语义不变。
- 移除模型不再要求确认，可直接撤销最近一次移除；删除整个供应商和清除凭据仍保留必要确认。协议覆盖留在折叠区。
- 模型 ID 保持稳定，本地名称继续通过原有管理员模型接口保存。连接保存仍保护已经保存的名称，避免旧快照覆盖新名称。
- 同一 ID 在不同供应商中的名称独立。能力详情仍按原有共享 Model Profile 合同保存，弹窗保留跨供应商生效说明。
- 排序在当前供应商内调整，保持其他供应商在全局模型顺序中的位置；保留已有全局排序数据。
- 停用供应商后模型不进入生成选择器，管理员仍能查看和编辑其模型；后续管理保存不会丢失停用供应商的排序与隐藏记录。
- RunningHub 应用／工作流、火山素材库密钥、CLI 检测与帮助、ModelScope LoRA 继续使用既有实现。
- 列表模型数量按供应商内模型 ID 去重；分类数量表示该分类条目数。供应商列表只显示新增勾选的「已选 N 个模型」，不再使用无说明的分数；英文区分单复数，数字使用语言对应的分组格式。
- 「前往创作」在工作台内切回画布入口；缺少必需密钥、没有模型、供应商停用或所有模型隐藏时留在设置并提示对应操作。独立演示只验证设置，不执行生成，点击该入口明确说明演示范围。

## 第二轮已确认原则

2026-11-09 用户要求从不懂技术的使用者出发：减少技术路径选择，文案按中文、英文各自习惯表达；界面能够表达的内容不再另写解释。数值必须说明含义并校验；可逆操作直接执行，影响不可逆时才二次确认。页面采用一个强调色和暖灰，同屏最多四种字号，并验证可读性与无障碍。

本页字号收敛为 12、14、16、20 px；复用共享组件的焦点和键盘机制。第二轮曾添加页面专用暖灰；随后用户指出背景与 Design Token 不一致，修订为复用共享主题背景和色板，移除该专用暖灰映射。调研中的主要发现为：长期展开的连接表单挤压模型区域（V-05 视觉焦点与层级）、获取／添加两个入口语义重叠（I-07 无需思考的选择）、每行常驻多个低频操作（I-06 视觉噪音）、旧空状态仍指向已经合并的 API 设置页（C-05 入口与页名一致）。

文案将面向用户的「本地名称」写作「显示名称 / Display name」，将地址写作「服务地址 / Server URL」；技术身份仍使用「模型 ID / Model ID」。密钥说明只在未配置时出现。新建密钥、登录与付费由用户在供应商网站完成，本次没有实际创建外部密钥。

## 前端职责

`api-settings.html` 是唯一设置页面。保留 URL 是为了兼容现有入口和管理员访问控制。

`api-settings.js` 管理供应商连接、模型清单变更和供应商专有工具；删除它原先的第二套模型行与可编辑 ID 行。`available-model-management.js` 作为该页的模型管理模块，唯一负责显示名称、显隐、顺序和能力入口；通过窄接口 `ProviderModels` 与 `ProviderConnections` 协作。模型保存的结果回写连接模块的名称快照，无需在两页之间来回加载。

`model-capability-workbench.js` 继续管理能力目录。加密包格式、生成接口与秘密存储边界保持原有合同；管理员模型清单新增对停用供应商的读取，公开生成清单仍排除停用供应商。
