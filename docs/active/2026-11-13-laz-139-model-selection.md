# LAZ-139：供应商内模型选择与自动填参

状态：已实现，本地回归通过；真实 Chrome 验收发现的官方文档格式兼容问题已修复，待后端重启后复测刷新。官网对照已完成，发现旧参数与供应商合同的差异，完整参数验收尚未通过。用户已完成 grilling 并确认下述范围。本文取代 2026-11-09 模型供应商规格中的来源切换、添加/显隐双状态、跨供应商能力编辑及前往创作行为。

## 已确认行为

- 目标是 APIMART 等供应商打开后的详情页；供应商首页排序不变。
- 当前供应商的远端清单与本地记录合并为一个可选择列表。选中即启用，未选中即关闭，选中模型优先。取消选中保留连接、名称和能力参数；重新选中继续使用。
- 保留名称/ID 搜索、媒体类型筛选、全选/全不选和展开余项。批量选择作用于全部匹配项，不限于当前展开部分；选择自动保存，保存期间避免重复交互。
- 每个供应商有独立浏览器缓存，缓存模型 ID、分类、名称及最近成功获取时间。打开详情先显示缓存和已配置模型；没有缓存或成功时间超过七天时拉取。页面停留期间没有轮询。手动刷新绕过期限。
- 拉取失败保留原列表和成功时间，可直接重试；连接地址、协议或凭据编辑使缓存失效。切换供应商或修改连接后，旧请求不能覆盖新页面。
- 「编辑模型参数」进入当前供应商已选模型的全部列表，跨图片、视频、文本显示。每行独立编辑按钮进入既有模型详情；不展示额外显隐开关。名称重命名保留。
- 参数读取与保存显式指定供应商；相同 Model ID 在其他供应商的配置不变。取消选中的模型从编辑列表退出，但配置不删除。
- 移除「前往创作」及其页面动作。

## 自动填参及恢复

沿用 Dreamina、Gemini API、APIMART 的确定性来源提取，不新增 AI 猜测或第三方搜索执行器。APIMART 扩展 Schema 中明确的参考媒体数量、布尔值域、分辨率、比例、输出数量、格式和透明背景等可映射字段进入现有合同。供应商未返回的信息保持原值，不承诺所有模型都有完整字段。

每个 Provider + Model 首次自动应用前备份完整旧合同（包括该媒体类型的各 Model Operation）。本次已授权自动值覆盖旧人工值。以后人工保存过的实际变化字段保留，自动刷新仅更新其余字段。未知支持状态不降级已有明确支持，缺失字段不清空已有值。

详情「更多 → 恢复自动填参前的参数」恢复当前供应商中该模型的整份初始备份，并把恢复产生的变化视作人工修改。后续自动应用不覆盖这份备份，不提供多版本历史管理。发布、备份、保护元数据及目录激活遵守原子回滚边界。

模型清单成功、能力应用失败时仍显示清单，但提示参数未完全应用；手动刷新可重试。没有可靠可用能力的模型仍可手动设置。

## 数据边界与兼容

- 浏览器缓存属于可丢弃 Device Cache，不包含密钥、选中状态或运行合同；清理后可重建。
- 选择复用原有供应商模型清单和 `visible` 存储。历史隐藏项映射为未选中，不自动启用；仅在产品界面消除双状态。
- 能力及迁移备份仍在安装级 `model-capability-workbench.json` 中，属于 Instance State。旧 Published 数据直接保留，无启动时破坏性迁移。
- 既有 Model ID、别名、名称、协议覆盖、供应商启停和其他供应商的选择状态继续保留。
- API 设置包仍导出当前能力，不导出自动填参历史；导入旧包不应清除目标安装已存在的迁移备份。
- `GET /api/admin/model-capability-matrix?provider_id=...` 返回独立投影；更新和恢复 API 必须携带 `provider_id`。未带供应商的只读汇总保留给目录标签，不能作为编辑身份。
- `POST /api/admin/model-capability-matrix/restore` 为管理员恢复入口，使用 `provider_id` 与 `model_id`。
- 不执行付费模型生成，不主动批量改写用户真实配置；运行中的管理员页面下次实际拉取时应用自动参数。

### 2026-11-13 真实 Chrome 验收

使用用户现有登录会话访问 `http://127.0.0.1:3000/`，APIMART 清单共 324 项，原有 11 项选中且排在前面。取消 Midjourney 后计数为 10，搜索后重新选中恢复为 11，重载并重新打开供应商仍保留选择。重开直接展示缓存，未出现拉取状态。中英文往返切换正常；APIMART 参数列表显示自身 11 个已选模型，GPT CLI 参数列表只显示自身 2 个模型。Nano Banana 2 的详情及恢复备份入口可打开，未执行真实备份恢复或付费生成。

实际手动刷新成功取得模型列表，但出现部分自动参数应用失败。独立调用同一官方资料采集器稳定复现：APIMART Seedream 参数页把两个 MDX `ParamField` 声明改为纯 Markdown 标签，既有精确标记校验误报文档变更。新增真实格式回归先失败，修复后 Discovery 与 LAZ-139 的 16 项测试通过，直接读取当前官方网页也能成功解析；扩大至原完整回归集后共 146 项通过，前端资源与 diff 检查通过。类型、默认值或图层上限改变仍拒绝应用。后端进程不自动重载，因此这次代码修复在当前服务上的刷新成功结果仍待重启复测。

用户补充要求对照模型官网参数；该核对区分模型原厂文档与 APIMART 实际接口范围。扩展模型 Schema 缺少上限或枚举时，页面保留旧配置，不应把 `auto_fill` 记录存在或模型清单拉取成功当成所有字段均获官网确认。

已核对全部 11 个已选模型，结果见[官方参数审计](2026-11-13-laz-139-official-parameter-audit.md)。明确差异包括 Banana Pro/2 的参考图上限 20 对文档 14，以及四个 GPT Image 型号的 20 对文档 16。Banana Pro/2 文档单请求数量为 1，当前配置分别为 4/8；当前 APIMART 连接模式为 `openai`，HTTP adapter 的 `native_count` 对这两个模型返回 true，不能仅凭 Generation Run 存在拆分框架认定当前路径已处理该差异。其他模式和未来批量能力应单独验证。此次研究没有把文档差异批量改写进真实配置，也未扩展条件透明、GIF/SVG 或 Midjourney 版本合同；这些覆盖缺口保留为待处理项。
