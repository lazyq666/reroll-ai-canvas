# ADR-0015: 前端资源指纹的唯一生成权威

- Status: Accepted
- Date: 2026-09-22

## Context

业务模块更新后，HTML 仍可能保留旧版本地址。独立的 UI、i18n、头像规则与请求时按应用版本覆盖引用，使依赖图容易不一致。新浏览器直接读取源码的测试无法暴露已有缓存中的旧代码。

## Decision

用显式开发阶段的统一生成器发现本地资源及引用，按内容与依赖计算指纹并同步源码。发布入口只读验证生成结果。运行时保持生成地址，HTML 重新验证，带指纹资源长期缓存。所有旧专用命令委托同一实现。

引用以完整字面量 URL 为发现接口；新增动态加载方式必须保持可发现并有测试。固定第三方快照以明确的路径、原因和内容锁排除。生成器包含未被引用的业务脚本盘点，新增文件不能静默逃过发布检查。

保留现有无构建工具的前端结构。无环依赖使用实际输出内容的摘要；循环依赖作为一组归一化计算，保证确定性与一次收敛。发布版本不参与资源身份。

## Alternatives considered

- 继续手工维护各模块版本：无法防止同类遗漏。
- 所有资源共用发布版本：每次发布使未变资源失效，且模块间引用仍需要同步。
- 启动时改写 HTML 或使用 mtime：违反 #33，并使机器与启动时间影响结果。
- 引入全站打包工具：迁移范围远超当前缓存合同，不是修复本问题的必要条件。
- 禁用缓存或每次随机参数：丢失未变化资源的缓存收益。

## Consequences

提交需要包含生成的引用与清单差异。引用写法成为开发约定，计算型加载器必须显式适配；第三方快照更新需要审查内容锁。真实浏览器保留缓存的升级对照进入必需发布检查。旧标签页自动升级、安全刷新和跨版本长期并存不在本决策范围。
