# ADR-0001：Workspace Data、Instance State、Device State 与 Device Cache 的边界

- 状态：已接受
- 日期：2026-07-28
- 修订：2026-07-30，将可再生大文件从 Device State 独立为 Device Cache
- 修订：2026-08-02，Issue #74 将账号域从 Workspace Data 解耦为稳定 Instance State
- 修订：2026-08-03，允许同一设备的多个源码目录服务隔离运行并共享 Instance State
- 后续决定：ADR-0006 局部取代“恢复页不提供新空 Workspace”的限制
- 后续决定：ADR-0007 局部取代 Prompt Template 封面必须进入通用 Managed Media 的限制
- 来源：Candidate 02，Issue #18 / #19 / #74

## 背景

早期决策把账号、角色与会话放进 Workspace Data，使“打开另一个内容目录”同时变成“替换账号域并退出登录”。Issue #74 确认账号是安装级身份：一个账号在所有 Workspace 中使用同一个角色，Workspace 不提供 membership 或按 Workspace 的角色。本文本次修订明确取代下文旧版本中“账号随工作区移动”的决定。

另一方面，API Key、访问令牌、CLI 登录状态和本机服务地址具有设备或秘密属性；媒体预览和下载模型虽然不一定敏感，却体积较大且可以重建。如果它们随工作区复制，会把一台电脑的凭据、连接和缓存带到其他目录或设备。

## 决策

用户选择的一个目录是完整的工作区。以下内容属于 Workspace Data：

- Smart Canvas、Managed Media、Prompt Library、Workflow、生成结果、历史记录和对话；
- 团队共享的模型选择、显示别名、用户工作流和非敏感生成默认值。

以下内容属于 Instance State：

- 管理员与其他账号、密码校验信息、账号申请和会话；
- `users.role` 所表达的安装级全局角色；
- 以 `workspace_id + user_id + project_id` 关联的 Project Access Grant；它只限制设计师可访问的内容，不改变全局角色；
- 账号关联的私有画布视图状态、分享令牌和审计记录。凡是引用内容的记录必须同时保存 `workspace_id`，不能只以 `canvas_id` 关联。

Instance State 不随 Workspace 打开、搬家或导出而替换或复制。同一设备上由不同源码
目录启动的本地服务默认共享 Instance State；Workspace 不拥有账号、membership 或角色。

以下内容属于 Device State（旧文档称 Local State）：

- API Key、访问令牌、CLI 登录状态及其他可复用凭据；
- 本机服务地址、硬件或性能设置；
- 启动器状态和当前设备选择的工作区目录。

Device State 以源码目录派生的稳定身份分区。不同源码目录拥有独立的启动器锁、端口
记录、服务身份和当前 Workspace 选择，因此可以同时运行；它们不得写入同一 Workspace。

以下内容属于 Device Cache：

- 可重新生成的媒体预览；
- 可重新下载并校验的抠图等运行模型；
- 其他删除后只影响首次加载耗时、不影响作品完整性的派生文件。

Workspace 模块是 Workspace Data 位置与内部布局的唯一业务入口。Instance State 模块是活动账号库及其恢复副本的唯一入口；Device State 模块只管理持久的本机状态，Device Cache 模块只管理可再生文件。普通 UI 和正常管理 API 只呈现“工作区目录”，不呈现内部子目录或账号库路径。

Generation Settings 采用显式字段归属：平台显示名、协议、启用与首选状态、模型清单、模型显示别名、工作流定义和非敏感生成默认值属于 Workspace Data；请求地址、请求端点和区域等连接参数属于 Device State，密钥与 CLI 登录状态继续使用本机凭据存储。旧版混合平台设置读取时先把本机字段保存到 Device State，再净化工作区副本；未列入归属白名单的字段只隔离到本机，不自动提升为共享设置。

每个工作区同一时间只允许一个 Infinite Canvas 服务写入。服务必须在执行 Workspace 业务写入或保存工作区选择前取得工作区使用权，并在正常关闭时释放。当前安装拥有持久的本机服务身份；异常退出后，只允许同一安装在确认旧进程已经结束时自动恢复使用。来自另一台服务器或无法确认来源的残留状态默认拒绝接管，并提示用户回到原服务正常关闭。对于云盘尚未同步删除的另一台服务器记录，操作者明确确认原设备服务已经停止后，可以通过一次显式启动参数接管；该参数不得绕过当前设备上的活动操作系统文件锁，也不得成为自动超时接管。该机制只依赖工作区内的使用状态、操作系统文件锁与操作者的显式恢复确认，不引入外部协调服务。

工作区管理只对管理员开放，并以“打开已有工作区”和“搬家到新位置”两个用户意图组织。服务本机的目录选择器是选择位置的唯一普通 UI 入口；远程浏览器不能提交或检查任意服务器路径。选择结果先经过只读业务摘要，展示 Smart Canvas、媒体、文件数量、容量、最近修改和操作提醒；摘要不展示“成员账号”，因为 Workspace 不拥有成员。在管理员明确确认前，当前工作区选择不会改变。

打开已有工作区继续通过 ApplicationRuntime 的受控重启安全点完成。确认后，当前服务先持有目标工作区的唯一使用权；有活动生成任务时默认等待，管理员也可以在重启页明确取消。只有到达安全点后才保存目标工作区选择并由启动器重启；旧进程不热切换内容依赖。这个过程不得撤销全局会话、替换 Instance 账号库或改变 `users.role`。检查、占用或切换准备失败时不发出重启信号，当前工作区继续可用。本机凭据、账号与连接配置都不参与内容切换。

搬家确认前由 Workspace 服务生成只读计划：来源和目标工作区目录、文件数量、总容量、活动生成任务及可携带性提醒。目标只能是可写且空间足够的空目录；已有工作区引导到“打开已有工作区”，普通非空目录、同址或互相包含的位置直接拒绝。支持本机磁盘、外接磁盘和已经完整同步到本机的云盘目录；出于工作区数据安全考虑，NAS、SMB、NFS 等局域网网络磁盘不属于支持范围，也不提供绕过开关。计划阶段不复制内容、不改变当前工作区选择，也不操作生成任务。

确认搬家后，ApplicationRuntime 先等待活动生成任务自然完成；管理员也可以明确取消这些任务并继续。真正开始搬家时运行时进入维护状态，统一阻止新的 HTTP 与 WebSocket 业务操作，排空已经进入的写请求，关闭实时连接和后台工作。工作区内容先复制到目标旁带有搬家标识的临时目录，来源与副本按相对路径、文件数量、总字节数和 SHA-256 内容摘要逐文件比较；使用状态、`data/auth.db*` 以及旧账号恢复文件都不参与复制。只有全部一致后才发布新目录、取得新工作区使用权、保存当前工作区选择并请求启动器重启。原工作区始终保留，全局会话不作废。复制、校验、切换或重启失败时恢复原工作区选择与使用权，且不在当前进程内热切换业务依赖。

每次搬家使用一个持久的操作编号。进度阶段、已处理文件数和字节数只允许单调前进，并通过轮询和可重连的 WebSocket 从本机状态恢复；同一目标的重复确认复用进行中的操作，不触发第二次复制或切换。失败记录只展示失败阶段和经过业务名称转换的工作区相对路径，不拼接底层绝对文件路径。重试总是创建新操作并从头复制；开始前只清理“目标名称 + 上次操作编号”精确匹配、且确认为普通目录的临时内容，未知目录和来源工作区不参与清理。搬家期间不提供取消或断点续传。成功重启后，进度页使用经过同源相对地址校验的返回位置，让管理员回到开始搬家前的页面。

启动时若已保存的工作区目录不存在、被移动或无法完整读取，运行时进入专用恢复阶段，不创建空白替代工作区。恢复页提供“重试当前工作区”“重新连接工作区”和“打开另一个已有工作区”；三条路径都保留 Instance 会话与全局角色。工作区携带一个稳定身份，本机只记录最后一次成功打开的身份；重新连接时两者必须一致，从而避免把另一工作区误认成移动后的原工作区。所有选择都先只读检查，到受控重启安全点才保存新位置；检查、准备或重启信号失败时继续停留在恢复页并保留原位置选择。

上述“不创建空白替代”继续禁止自动替代。ADR-0006 后续允许本机用户在恢复页主动选择并
确认空目录，经过 SQLite 完整初始化和校验后创建新的 Workspace；它不把新内容伪装成原
Workspace，也不修改 Instance State。

新导入的本地图片、视频、音频和受支持文件必须先复制到当前工作区的 Managed Media 区域，再向 Smart Canvas、Workflow 和 Generation Run 返回工作区相对引用。托管文件使用内容摘要作为稳定标识和小写文件名，相同内容复用同一份副本；引用统一使用正斜杠，不保存来源设备的绝对路径，因此工作区换目录或换受支持的操作系统后仍可解析。只读工作区摘要会统计当前设备无法访问的旧绝对媒体引用并提示用户，但这类警告不阻止打开，也不会触发全盘搜索、自动改写或替换。

Smart Canvas、项目分类、对话、生成历史、自定义工作流、RunningHub 工作流配置和提示词库统一通过当前 Workspace 实例定位。保存格式、列表顺序和已有内容不在本次迁移中转换；切换到不同工作区时，这些业务内容随工作区隔离，调用方不得回退读取安装目录或默认工作区中的同类文件。版本记录、分享与协作仍沿用现有业务协议，只替换其存储位置入口。

导入媒体、生成输入与结果、本地上传统一通过当前 Workspace 的产物入口定位，已有 `/assets/...` 与兼容下载地址继续可解析。可重新生成的媒体预览和可重新下载的运行模型通过 Device Cache 定位，不随工作区搬家。应用更新的暂存内容与回退副本由 Workspace 管理；账号迁移恢复副本只由 Instance State 管理。更新文件白名单只允许应用代码与公开资源，明确排除账号、平台凭据、工作区内容、Instance State、Device State 和 Device Cache。进程工作目录或安装位置变化不得改变这些业务与维护文件的归属。

Contract 阶段已经完成：业务代码只通过当前 Workspace 实例定位业务内容，通过 Instance State 定位账号域，不再读取旧成对路径环境变量、Workspace 内的活动账号库、安装目录中的同类文件或源码目录回退。设备只保存一个已确认的工作区目录；该目录无效时必须进入初始化或恢复流程，不能创建空白工作区代替。启动、打包、更新、回退和恢复均遵守同一边界，且不得把账号、平台凭据、工作区内容或本机状态带入应用更新包。

## 影响

- 旧 Workspace 账号迁移必须使用 SQLite 一致性快照，先验证 Instance 活动副本与恢复副本，再删除源 `auth.db` 及 WAL/SHM；失败保留源，重试幂等。
- Instance State 已有账号时永远具有权威性；其他 Workspace 的旧账号库只归档供恢复，绝不自动合并或覆盖。
- 打开或搬动 Workspace 只切换内容；现有账号、会话和全局角色继续有效。
- Project Access Grant 保存在 Instance State，并按 Workspace 身份隔离；管理员可为设计师多选可访问的 Project。
- 工作区检查、搬家和导出必须证明 Instance State、Device State 中的秘密以及 Device Cache 中的派生大文件没有进入 Workspace Data。
- 本机已有的服务凭据可以在打开另一个工作区后继续使用，但目标工作区的共享非敏感生成设置具有业务权威性。
- 两个服务不能同时写入同一工作区；未知来源的残留使用状态不会被自动清除，其他服务器的残留记录只允许在操作者明确确认原服务已停止后显式接管。
- 分享、私有视图和内容审计使用 `workspace_id + canvas_id` 等组合关联，避免不同 Workspace 的同名内容串联。

## 不采用的方案

- 每个 Workspace 单独保存账号、角色或 membership：会让内容切换替换身份域，且与一个用户跨 Workspace 使用同一角色的产品决定冲突。
- 自动合并不同旧 Workspace 的用户：同名账号、密码和角色冲突没有可靠的无交互决策，会破坏可恢复性。
- 将所有生成设置一起搬动：会泄露秘密和设备专属连接。
- 让调用方自行选择保存位置：会重新分散工作区边界，无法统一检查、搬家和恢复。
