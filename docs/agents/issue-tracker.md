# Issue tracker: Linear

Linear is the source of truth for bugs, requirements, investigations, and development tasks.

Existing GitHub Issues remain historical references. New work does not require a GitHub Issue or a GitHub Project entry.

## Workflow

| Work status | Meaning |
| --- | --- |
| `Todo` | Accepted work that has not started |
| `In Progress` | Work is actively being implemented |
| `Review` | A pull request or completed implementation is awaiting review or verification |
| `Done` | The work is merged or verified |

Use the corresponding statuses in Linear.

## Rules

- Search existing Linear work before creating a new issue.
- Reuse or extend an existing Linear issue when it covers the same work.
- Update the Linear status as work starts, enters review, and is verified.
- Link the pull request to the Linear issue when one tracks the work.
- Preserve relevant acceptance criteria, diagnostics, priority, and source context in the Linear issue.

## Pull requests

Pull requests describe implementation and verification. Record product requirements in Linear when the work needs tracking.
