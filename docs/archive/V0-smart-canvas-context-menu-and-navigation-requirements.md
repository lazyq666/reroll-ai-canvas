# Infinite Canvas V0：智能画板节点右键菜单与 Figma 式导航需求文档

> 文档状态：Draft v0.2  
> 创建日期：2026-07-22  
> 适用页面：`/static/smart-canvas.html`  
> 适用版本：V0  
> 评审状态：待产品、设计、技术评审

## 1. 文档摘要

本期为智能画板补齐节点右键上下文菜单，并把画布导航调整为更接近 Figma 的“指针 / 抓手”双模式：

1. 右键节点时打开上下文菜单，提供复制、粘贴、删除等通用操作。
2. 菜单同时依据节点类型、生成状态、选择状态和结构关系动态组合；图片首期增加“图片反推提示词”和“替换图片”。
3. 媒体内容支持从右键菜单直接加入当前用户的资产库。
4. 移除节点右上角的删除按钮，节点删除入口统一为右键菜单和键盘快捷键。
5. 画板默认进入指针模式；`H` 切换常驻抓手，`V` 返回指针；按住空格或鼠标中键临时进入抓手。
6. 指针模式下拖动画布空白区域不再平移视口；抓手模式下拖动才平移视口。

本文中的“右键菜单”指 Context Menu / 上下文菜单，而不是只用于展示说明文字的 Tooltip。界面文案统一使用“右键菜单”或“上下文菜单”。

## 2. 背景与现状

### 2.1 当前体验问题

- 普通节点被右键时不执行任何操作；智能分组被右键时直接打开“向分组添加内容”的创建菜单，缺少节点管理入口。
- 复制、粘贴和删除能力虽然已有快捷键，但发现成本高，鼠标用户缺少就近入口。
- 图片节点已有预览、裁剪、扩图、遮罩、画笔、宫格和下载等悬浮操作，但缺少反推提示词和原位替换。
- 节点右上角长期显示或悬停显示删除按钮，容易误触，也与右键菜单的信息架构重复。
- 当前默认在画布空白处按下左键即可平移，工具栏里的 `V` 和 `H` 实际都会回到同一个“非标注”状态，没有真正区分指针与抓手。
- 当前鼠标中键可以平移，但空格临时抓手尚未实现。

### 2.2 当前技术基础

智能画板采用 FastAPI + 原生 HTML/CSS/JavaScript，不使用 React、Vue 或独立组件框架。核心实现集中在：

- `static/smart-canvas.html`：画板 DOM、工具栏、弹窗和面板。
- `static/js/smart-canvas.js`：节点数据、渲染、选择、拖拽、快捷键、素材库和生成逻辑。
- `static/css/smart-canvas.css`：节点、浮动工具栏和画板视觉样式。
- `static/js/i18n/smart-canvas.js`：中英文案。
- `main.py`：画布、上传、资产库、视觉模型和提示词反推相关接口。

现有能力可直接复用：

- `copySelectedNodes()`、`pasteNodes()`：节点内存剪贴板。
- `deleteSmartNodes()`：节点删除、连线清理、撤销和保存。
- `addUrlToAssetLibrary()`：把画布媒体写入当前资产库或本地素材目录。
- 现有上传链路：把本地文件上传后生成可保存的媒体 URL。
- `caption_image_with_provider()`：通过已配置且支持视觉输入的模型描述图片。
- `nodeClipboard`、`selectedId`、`selectedIds`、`selectedImage`：单选、多选和多图节点内的媒体焦点。

### 2.3 已知框架限制

- 节点由 `render()` 拼接 HTML 后整体绑定事件，不适合引入重量级菜单组件；本期应使用一个复用的全局菜单 Portal。
- 节点剪贴板目前只存在于当前页面内存，刷新页面后失效，也不等同于系统剪贴板中的任意 JSON。
- 全局资产库接口只接受本服务可解析的 `/assets` 或 `/output` 媒体；外部 URL 必须先导入或上传到本地。
- 图片、视频和音频当前都使用 `smart-image` 节点结构，差异需要依据媒体项的实际 `kind` 判断，不能只看 `node.type`。
- 提示词、循环、智能分组、区块、画笔标记和文字标记分别使用 `smart-prompt`、`smart-loop`、`smart-group`、`smart-section`、`smart-brush`、`smart-text`。
- 分享页为独立只读页面；本需求不应为分享访客暴露编辑菜单或创作接口。

## 3. 产品目标

### 3.1 目标

- 让用户可以仅凭鼠标发现并完成高频节点操作。
- 保持不同节点菜单与节点能力一致，避免展示无法执行的操作。
- 让图片反推和替换保持在当前画板上下文内，不破坏节点关系。
- 减少删除误触，并保留快捷键的高效路径。
- 建立清晰、可预测的指针 / 抓手状态，使选择节点和移动视口互不混淆。
- 在不大改现有数据结构和服务架构的前提下交付。

### 3.2 成功标准

- 任意可编辑节点被右键后，100ms 内出现与该节点匹配的上下文菜单。
- 用户可从菜单完成节点复制、粘贴和删除，结果与现有快捷键一致。
- 已生成的图片、视频等结果节点可按原生成快照再次生成，新结果不会覆盖当前结果。
- Selection、媒体 Group、智能分组、区块和分组成员都有与自身结构匹配且命名明确的结构操作入口。
- 图片反推成功后可查看、复制并应用结果，且不会未经确认覆盖用户正在编辑的提示词。
- 替换图片后节点 ID、位置、尺寸、连线和分组/区块归属保持不变。
- 默认左拖画布空白处不再平移视口；`H`、空格和鼠标中键均可按定义平移。
- 节点右上角不再出现删除按钮。
- 原有生成、编辑、分组、区块、连线、素材库、滚轮缩放和快捷键功能不回退。

## 4. 非目标

本期不包含：

- 移动端长按菜单和完整触屏手势设计。
- 跨浏览器、跨标签页或刷新后仍保留的节点系统剪贴板。
- 自定义菜单项、插件菜单或用户自定义快捷键。
- 节点重命名体系、图层面板、锁定、隐藏和层级排序能力。
- 把所有顶部悬浮图片编辑工具迁移到右键菜单；现有浮动工具栏可以继续保留。
- 对正在执行的远端生成任务做真正的服务端取消；删除节点仍只按现有逻辑移除画板对象。
- 改造滚轮行为。滚轮继续以当前逻辑围绕指针位置缩放画布。
- 完全复制 Figma 的全部选择修饰键。现有连线擦除、分组和标注快捷键优先保持兼容。
- 视频内容反推、音频转写或任意节点的 AI 解释。

## 5. 术语与对象

| 术语 | 定义 |
|---|---|
| 节点 | 画板中的可选择对象，包括媒体、提示词、循环、分组、区块和标注。 |
| 媒体节点 | 数据类型为 `smart-image`，内容可能是图片、视频、音频或多个媒体项。 |
| 节点级操作 | 对整个节点及其连线关系生效，例如复制节点、删除节点。 |
| 内容级操作 | 对节点内某一个媒体项生效，例如替换一张图片、反推一张图片。 |
| 上下文菜单 | 在鼠标右键位置出现、依据目标动态生成的操作菜单。 |
| 基础工具 | 用户主动选择后持续生效的指针、抓手、画笔、文字或区块工具。 |
| 临时抓手 | 按住空格或鼠标中键时覆盖基础工具的临时平移状态，释放后恢复。 |

## 6. 用户故事

- 作为画板用户，我希望右键节点就能看到可用操作，而不必先记住快捷键。
- 作为高频用户，我希望右键操作与 `Cmd/Ctrl + C`、`Cmd/Ctrl + V`、`Delete` 结果一致。
- 作为图片创作者，我希望直接对画板图片反推提示词，并决定是否把结果填入输入框。
- 作为图片创作者，我希望替换图片但保留当前节点位置、大小和上下游连接。
- 作为生成任务用户，我希望右键已经生成的图片或视频按原提示词、原参数和原输入再次生成一个新结果。
- 作为素材整理者，我希望把画板中的媒体快速保存到正在使用的资产库目录。
- 作为画板整理者，我希望对临时多选进行编组，对真正的 Group 解散分组，并把误放入分组的节点移出，而不会混淆这些不同操作。
- 作为熟悉 Figma 的用户，我希望默认用指针选择对象，只在抓手状态下拖动画布。
- 作为笔记本用户，我希望按住空格即可临时平移；作为鼠标用户，我希望中键始终可以临时平移。

## 7. 总体交互原则

1. 右键目标决定基础菜单，节点状态和结构关系追加状态化操作，选择状态决定操作范围。
2. 单节点菜单可以显示类型、生成状态和结构关系专属操作；混合多选只显示对整组选区安全的通用及编组操作。
3. 不可执行的固定操作显示为禁用，并给出简短原因；与当前类型完全无关的操作不显示。
4. 节点级“删除”始终删除节点；多图中的“删除此媒体”必须使用不同文案，避免语义混淆。
5. 任何异步操作先关闭上下文菜单，再通过加载状态、结果面板或 Toast 反馈进度。
6. 菜单操作不得绕过现有撤销、保存、权限和素材路径校验。
7. 输入框、可编辑文字、选择框、弹窗和面板内继续保留正常文本输入行为，不拦截空格、`V`、`H` 或浏览器原生文本右键菜单。
8. 菜单不能只按 `node.type` 写死；至少要经过“目标内容类型 → 任务状态 → 生成来源 → 容器关系 → 选择范围 → 权限”的能力判断。

## 8. 功能需求：节点上下文菜单

### 8.1 FR-CM-001：打开与关闭

- 在可编辑智能画板中，鼠标右键命中 `.image-node` 时阻止浏览器默认菜单并打开节点上下文菜单。
- 菜单锚定在本次右键的屏幕坐标；靠近窗口边缘时自动向内翻转，不能超出可视区域。
- 同一时间只能存在一个上下文菜单。
- 以下行为关闭菜单：
  - 点击菜单外区域。
  - 按下 `Escape`。
  - 开始平移、缩放、拖动、调整节点尺寸或连线。
  - 切换工具、打开弹窗或切换画布。
  - 再次在其他目标上右键。
- 在节点内的 `input`、`textarea`、`select`、`contenteditable` 文本编辑区域右键时，不打开节点菜单，保留浏览器文本菜单。
- 只读分享页不显示该菜单。

### 8.2 FR-CM-002：右键与选择范围

- 右键未选中的节点：先把它设为唯一选中节点，再打开单节点菜单。
- 右键当前多选集合中的节点：保留整个多选集合，菜单中的复制和删除作用于整个选区。
- 右键当前单选节点：保持选中状态，不触发重新渲染导致的闪烁。
- 右键多图节点中的具体媒体缩略图：除选中所属节点外，还要记录对应 `nodeId + imageIndex`，图片专属操作只作用于该媒体项。
- 混合多选时不显示“反推提示词”“替换图片”等单内容操作。
- 菜单打开本身不写入撤销栈、不保存画布。

### 8.3 FR-CM-003：通用菜单项

所有节点至少支持以下节点级操作：

| 菜单项 | 快捷键提示 | 行为 |
|---|---|---|
| 复制节点 | `⌘C` / `Ctrl+C` | 复用现有节点复制逻辑；多选时复制完整选区及选区内部连线。 |
| 创建副本 | `⌘D` / `Ctrl+D` | 不占用或依赖剪贴板，直接在原节点右下方创建副本；多选时保留相对布局和选区内部连线。 |
| 粘贴节点 | `⌘V` / `Ctrl+V` | 把内部节点剪贴板内容粘贴到本次右键位置附近。剪贴板为空时禁用。 |
| 删除节点 / 删除 N 个节点 | `Delete` / `Del` | 复用现有删除逻辑，立即删除并可通过撤销恢复。危险操作使用红色。 |

补充规则：

- 菜单“粘贴节点”只处理 `nodeClipboard`；系统剪贴板图片仍通过现有 `Cmd/Ctrl + V` 路径导入。
- “创建副本”复用现有节点克隆和 ID/内部连线重映射规则，不读取或改写 `nodeClipboard`；快捷键作为本期新增，与 `Alt + 拖动` 的既有复制方式并存。
- 粘贴锚点使用本次右键对应的世界坐标，不依赖菜单打开后的鼠标移动。
- 粘贴后选中新节点；多个节点的相对位置和内部连线保持不变。
- 删除后同步清理相关连线、输入引用和容器成员关系，并调用现有保存逻辑。
- 区块删除采用第 8.8 节的专属文案与规则，不使用含糊的“删除节点”。

### 8.4 FR-CM-004：加入我的资产

- 具有可保存媒体内容的单个媒体节点或智能分组显示“加入我的资产”。
- 右键具体媒体项时只保存该项；右键媒体节点空白区域时：
  - 单媒体节点保存该媒体。
  - 多媒体节点显示“加入我的资产（N 项）”，批量保存节点内全部有效媒体。
- 默认目标为资产面板最近一次选择的资产库和图片/媒体目录。
- 菜单项右侧可提供子菜单：
  - “保存到：{最近目录}”。
  - “选择其他位置…”。
- 当前目标不存在或不可写时，打开轻量目标选择弹窗，不允许静默保存到未知目录。
- 保存成功后提示“已加入 {资产库}/{目录}”；批量保存显示成功数和失败数。
- 对全局资产库保存时复用 `/api/asset-library/items` 或批量接口；对“本地素材”保存时复用 `/api/local-assets/import-urls`。
- 外部 URL 必须先通过现有导入/上传链路转换为服务端可管理的本地媒体，再写入资产库。
- 已存在相同来源时不覆盖原文件；沿用资产库当前的重名和去重策略。
- 提示词、循环、区块、画笔和文字节点不显示此项。提示词的资产化使用已有“保存为提示词预设”，不与媒体资产混用。

### 8.5 FR-CM-005：图片专属菜单

当右键目标媒体的实际类型为图片时，增加：

| 菜单项 | 行为 |
|---|---|
| 图片反推提示词 | 调用视觉模型分析目标图片，打开可编辑结果面板。 |
| 替换图片… | 选择一张本地图片并原位替换目标媒体项。 |
| 预览 | 复用现有图片预览。 |
| 编辑图片 | 二级菜单，复用现有裁剪、扩图、遮罩、画笔和宫格能力。 |
| 下载 | 复用现有下载逻辑。 |
| 加入我的资产 | 按第 8.4 节保存目标图片。 |

“图片反推提示词”和“替换图片”必须位于菜单第一组，优先于低频编辑能力。

### 8.6 FR-CM-006：图片反推提示词

- 仅对真实图片启用；视频、音频、空上传节点和加载中的占位内容不显示。
- 点击后立即关闭菜单，并在目标节点附近或全局 Toast 显示“正在反推提示词…”。
- 同一图片同一时间只能存在一个反推请求，重复触发时聚焦已有任务状态。
- 服务端复用 `caption_image_with_provider()`，但需要新增面向画板媒体 URL 的安全接口；接口必须：
  - 只接受当前用户有权访问的画布及其中实际引用的图片。
  - 只解析允许的 `/assets`、`/output` 或已受控导入路径。
  - 不接受客户端绝对路径，也不在响应中返回服务器绝对路径。
  - 使用管理员已配置、设计师可调用的视觉模型，不向前端返回 API Key。
- 建议接口：`POST /api/smart-canvas/image-caption`。
- 建议请求字段：`canvas_id`、`node_id`、`image_index`、可选 `provider`、`model` 和反推指令。
- 成功后打开“反推提示词”结果面板，至少包含：
  - 可编辑的提示词文本。
  - “复制提示词”。
  - “填入提示词输入框”（主操作）。
  - “创建提示词节点”（次操作）。
- 反推完成时不得自动覆盖 Composer 中的现有草稿；只有用户点击“填入提示词输入框”后才写入。
- “填入提示词输入框”后保持原图片节点为当前参考对象，使用户可以继续执行图生图或编辑生成。
- “创建提示词节点”在目标图片右侧创建 `smart-prompt`，写入反推结果，并连接到原图节点时必须遵循当前连线兼容规则；若无明确安全连线方向，仅创建节点、不自动连线。
- 请求失败时保留画板状态，显示可理解错误，例如“当前模型不支持图片输入”“图片文件不可访问”“反推服务超时”，并允许重试。
- 反推结果默认为临时结果，不自动写入图片元数据或资产 Caption。

### 8.7 FR-CM-007：替换图片

- 点击“替换图片…”后打开只接受 `image/*` 且单选的文件选择器。
- 用户取消选择时不产生任何变更、撤销记录或保存请求。
- 上传成功后，只替换右键命中的图片项，并保持：
  - 节点 ID。
  - 节点世界坐标。
  - 用户显式设置的节点宽高。
  - 节点输入/输出连线。
  - 在智能分组和区块中的归属。
  - 多图节点中的原索引和其他媒体项顺序。
- 替换后更新文件名、媒体类型、自然宽高、预览 URL 等与新图片相关的字段。
- 清理旧图片的临时云链接、旧尺寸缓存和只属于旧生成结果的瞬态字段，不能把旧图的像素元信息错误继承给新图。
- 替换是一次可撤销操作；撤销后恢复原图片项。
- 上传或解码失败时保留原图，不写入撤销栈，并显示错误提示。
- 加载中、生成中或结果尚未落盘的占位媒体不允许替换，菜单项禁用并提示原因。

### 8.8 FR-CM-008：其他节点类型菜单

首期按以下矩阵生成菜单。通用项始终位于最后一组，删除始终为最后一项。

| 节点/内容类型或状态 | 类型/状态专属操作 |
|---|---|
| 空上传节点 | “选择文件…”；不显示加入资产。 |
| 已导入图片 | “图片反推提示词”“替换图片…”“预览”“编辑图片”“下载”“加入我的资产”。没有生成快照时不显示“再次生成”。 |
| 已生成图片 | 在图片操作基础上增加“再次生成”“查看生成信息”“复制生成提示词”；支持时增加“以此为参考继续生成…”。 |
| 已导入视频 | “播放/预览”“替换视频…”“提取画面”“下载”“加入我的资产”。不显示图片反推和再次生成。 |
| 已生成视频 | 在视频操作基础上增加“再次生成”“查看生成信息”“复制生成提示词”。 |
| 音频媒体 | “播放”“替换音频…”“下载”“加入我的资产”；有完整生成快照时增加“再次生成”。不显示图片反推。 |
| 其他文件或文本结果 | 按可预览能力显示“预览/复制内容”“下载”；有完整生成快照时增加“再次生成”。 |
| 生成中/排队中 | 显示只读状态“生成中…”或“排队中…”；支持查询的任务显示“查询进度”。不允许再次生成和替换。 |
| 生成失败且可恢复 | 显示“查询结果”或“重试生成”；重试必须沿用失败任务的生成快照。 |
| 多媒体 Group | 针对命中的媒体显示内容操作；命中节点空白区域时显示“拆分为独立节点”“批量预览”“宫格拼接”“批量下载”“批量加入资产”。 |
| 历史结果 Group | “预览历史结果”“恢复此结果为当前结果”“拆分为独立节点”；恢复仅在命中具体历史媒体且来源节点仍存在时显示。 |
| 提示词节点 | “编辑提示词”“复制提示词”“保存为提示词预设”；启用 LLM 时显示“运行提示词节点”，已有运行结果时文案为“再次运行提示词节点”。 |
| 循环节点 | “运行循环”；运行中改为“停止循环”；完成后显示“再次运行循环”。 |
| 智能分组 | “添加节点…”“运行分组/再次运行分组”“整理排列”“预览”“宫格拼接”“批量下载”“批量加入资产”“解散分组”。无内容时禁用不适用项。 |
| 智能分组内成员 | 在自身类型菜单中增加“移出分组”。多选成员属于同一分组时显示“将所选节点移出分组”。 |
| 区块 | “重命名区块”“切换颜色”“仅删除区块，保留内容”“删除区块及内容”。最后一项为红色。 |
| 存在输入/输出连线的节点 | 增加“断开连接”二级菜单：“断开所有输入”“断开所有输出”“断开全部连接”。 |
| 画笔标记 | 通用复制、粘贴、删除。 |
| 文字标记 | “编辑文字”，以及通用复制、粘贴、删除。 |

兼容规则：

- 智能分组原先右键直接打开创建菜单；本期改为打开分组上下文菜单，并通过“添加节点…”继续进入原创建菜单。
- 智能分组双击添加内容的现有入口保持不变。
- 多媒体 `Group` 和 `smart-group` 是两种不同结构，但都复用现有 `ungroupNode()`；界面分别使用“拆分为独立节点”和“解散分组”。
- 区块沿用当前 `Delete` 删除区块及内容、`Cmd/Ctrl + Delete` 仅删除区块并保留内容的语义，但右键菜单必须用完整文案显式区分。
- 现有节点内按钮和图片顶部浮动编辑工具保留；本期只统一删除入口，不强制迁移全部功能。

### 8.9 FR-CM-009：空白画布右键

- 右键画布空白区域继续打开现有创建菜单，不打开节点菜单。
- 创建位置使用右键对应的世界坐标。
- 指针、常驻抓手和临时抓手模式下都可以右键打开；若前一手势已经产生平移，则本次 `contextmenu` 不得误开菜单。
- 双击空白处打开创建菜单的现有能力保持不变。

### 8.10 FR-CM-010：菜单视觉与可访问性

- 新菜单使用 `static/css/design-tokens.css` 中的 `--ui-*` 语义 Token，兼容浅色和深色主题。
- 菜单使用 Lucide 图标，不引入新的图标运行时或前端依赖。
- 推荐宽度 220–260px，单行高度不低于 32px；危险操作使用语义危险色。
- 菜单项显示文案、可选快捷键和可选二级菜单箭头。
- 菜单容器使用 `role="menu"`，菜单项使用 `role="menuitem"`。
- 支持 `ArrowUp`、`ArrowDown` 移动焦点，`Enter` 执行，`Escape` 关闭并把焦点还给画板。
- 禁用项具有 `aria-disabled="true"`，不能仅依赖颜色表达状态。
- 支持键盘 `ContextMenu` 键或 `Shift+F10` 在当前单选节点旁打开菜单；没有选中节点时不执行。

### 8.11 FR-CM-011：菜单能力组合模型

菜单不是为每个 `node.type` 维护一份互相独立的完整 HTML，而是按以下层次组合，后层可以禁用或替换前层操作：

1. **选择层**：单选、多选、右键目标是否属于当前选区。
2. **基础类型层**：媒体、提示词、循环、智能分组、区块、画笔、文字。
3. **内容层**：图片、视频、音频、文本、文件、空内容、多内容。
4. **任务状态层**：空闲、排队、生成中、成功、失败、可恢复。
5. **生成来源层**：导入素材、生成结果、历史结果；是否具有完整生成快照。
6. **结构关系层**：独立节点、媒体 Group、智能分组、分组成员、区块、区块成员。
7. **连线层**：是否有输入连线、输出连线或工作流上下游。
8. **权限层**：可编辑、只读、可使用模型、可写资产库。

菜单项推荐按以下分组排序：

1. 当前最重要的执行操作：运行、再次生成、查询结果、停止循环。
2. 内容操作：反推、替换、预览、编辑、提取画面、下载、加入资产。
3. 结构操作：创建分组、拆分、解散、移出分组、创建区块、断开连接。
4. 通用操作：复制、粘贴、删除。

同一个菜单不得出现语义重复的操作。例如已有“再次生成”时，不再同时出现含义不清的“运行”；智能分组显示“解散分组”时不再显示“拆分媒体 Group”。

### 8.12 FR-CM-012：已生成结果再次生成

- 图片、视频、音频或其他生成结果只有具备该引擎重新提交所需的完整快照时才显示“再次生成”：
  - 原运行参数：必须存在 `runSettings`，包括引擎、供应商、模型、尺寸、数量和模型专属参数。
  - 原提示词：优先使用 `runModelPrompt`，否则使用 `runPrompt`；仅当 `smartRunNeedsPrompt(runSettings)` 为真时强制要求非空。
  - 原输入引用：使用 `runInputRefs`；仅当对应模型/工作流要求媒体输入时强制要求有效，纯文生或无输入工作流允许为空。
- 不能只依据文件名、媒体类型或 `generatedResult` 判断可再次生成；用户上传或从资产库拖入的媒体不显示该操作。
- 只要存在部分生成元数据，仍可显示“查看生成信息”或“复制生成提示词”；这两个只读操作不依赖“再次生成”一定可用。
- “查看生成信息”至少展示生成时间、引擎/供应商、模型、提示词、尺寸/时长、数量和可公开的模型参数；API Key、服务器路径和其他敏感配置不得展示。
- “复制生成提示词”复制用户可读的 `runPrompt`；若只有模型实际接收的 `runModelPrompt`，需要明确标注“模型提示词”，不能伪装成原始用户输入。
- 点击“再次生成”后，按保存的生成快照发起一笔新任务：
  - 使用原提示词、原模型参数和原始输入引用。
  - 不把当前结果媒体自动追加为新的参考输入。
  - 不读取用户此刻在 Composer 中尚未保存的草稿或当前全局模型参数。
  - 当前结果保持不变，在其右侧或同一来源节点的结果列中创建新的兄弟结果节点。
  - 新结果与原结果共享来源语义，但拥有独立节点 ID、任务状态、日志和撤销记录。
- 随机参数遵循原快照：原配置为随机种子/随机值时重新取随机值；原配置锁定固定种子时继续使用固定值。
- 原供应商或模型已经被删除、禁用或当前用户无使用权限时，不得静默换用其他模型；显示“原生成模型已不可用”，并提供“使用当前参数生成…”作为显式备选入口。
- 原输入引用失效时，不发起残缺任务；结果面板列出失效输入，并允许用户重新指定后再生成。
- 当前节点处于排队、生成中或查询中时，“再次生成”禁用，文案显示当前状态。
- 再次生成失败不得修改或删除原结果；错误进入正常生成日志，并允许再次重试。
- “再次生成”和“以此为参考继续生成”必须区分：
  - **再次生成**：复用原配方和原输入，得到同条件的新结果。
  - **以此为参考继续生成…**：把当前结果作为新输入，打开 Composer 供用户修改提示词和参数；仅在当前引擎/模型支持该媒体作为输入时显示。

### 8.13 FR-CM-013：Selection、Group 与容器解绑

界面禁止使用一个笼统的“解绑”覆盖不同数据结构，按以下语义提供操作：

| 当前对象 | 菜单文案 | 行为 |
|---|---|---|
| 多选 Selection，节点尚未形成容器 | 创建分组 | 复用 `groupSelectedNodes()`，把可编组节点创建为 `smart-group`。 |
| 多选 Selection | 创建区块 | 复用 `createSectionFromSelection()`，只增加整理容器，不改变生成关系。 |
| 多选 Selection | 整理选中 | 复用现有选区整理能力。 |
| 多选 Selection | 取消选择 | 仅清空 `selectedId/selectedIds/selectedImage`，不进入撤销栈、不修改节点。 |
| 多媒体 Group（一个媒体节点内含多个媒体项） | 拆分为独立节点 | 复用 `ungroupNode()`，按当前顺序和平铺布局创建独立媒体节点。 |
| 智能分组 `smart-group` | 解散分组 | 复用 `ungroupNode()`；释放媒体与提示词/循环成员并删除分组容器。 |
| 智能分组中的单个成员 | 移出分组 | 只解除该成员与分组的成员关系，保持节点本身、位置、连线和内容。 |
| 同一智能分组中的多个已选成员 | 将所选节点移出分组 | 批量解除成员关系；属于其他分组的节点不受影响。 |
| 区块 | 仅删除区块，保留内容 | 删除区块容器，保留内部节点、位置和生成连线。 |
| 历史结果 Group 中的具体结果 | 恢复此结果为当前结果 | 把该结果恢复到对应来源节点，现有当前结果进入历史；不覆盖或丢弃历史。 |

补充规则：

- Selection 是临时界面状态，不存在“解散 Selection”；只使用“取消选择”。
- 多选中包含 `smart-group` 时，菜单可以显示“解散所选分组”，但只处理真实分组节点；普通选中节点不被删除或拆分。
- 结构操作必须可撤销，并在结束后把被释放的节点设为多选，便于用户继续移动或重新编组。
- 解散分组不应无条件删除成员之间原有的有效连线；只清理以已删除容器本身为端点的连线和容器引用。
- “移出分组”不得改变节点世界坐标。若当前紧凑成员使用分组内部布局，释放后应换算并保留屏幕可见位置。

### 8.14 FR-CM-014：多选菜单

- 当 `selectedNodeIds().length > 1` 时，右键选区中的节点保留选区并生成多选菜单。
- 多选菜单按选区能力显示：
  - 始终显示：复制所选、创建副本、粘贴节点、删除所选、取消选择。
  - 至少两个可编组节点：创建分组。
  - 至少一个可整理节点：创建区块、整理选中。
  - 全部为可保存媒体：批量加入我的资产、批量下载。
  - 全部是同一智能分组成员：将所选节点移出分组。
  - 包含真实分组：解散所选分组，并在副文案显示实际处理数量。
  - 全部具有完整且兼容的生成快照时：显示“分别再次生成 N 个结果”；不同引擎可以分别提交，不合并为一笔任务。
- 混合多选不显示替换图片、图片反推、恢复历史结果等需要单一明确内容目标的操作。
- 多选菜单中的数量来自执行前实时校验，不能使用菜单打开时已经过期的缓存数量。

### 8.15 FR-CM-015：连线与任务状态操作

- 节点存在连线时显示“断开连接”二级菜单：
  - 断开所有输入。
  - 断开所有输出。
  - 断开全部连接。
- 断开连接只修改连线、`inputNodeIds` 和相关输入引用，不删除任何节点；操作可撤销。
- 工作流运行中不得通过断开连接改变正在执行任务的快照；断开只影响后续运行。
- 排队或生成中的普通媒体任务，如果后端没有可靠取消能力，只显示“查询进度”，不能提供一个实际上只删除节点的“取消生成”。
- 循环任务已有停止能力时显示“停止循环”；点击后沿用当前停止流程。
- 可恢复失败任务显示“查询结果”；确认失败且生成快照完整时显示“重试生成”。
- 状态操作执行前再次读取实时节点状态，避免协作更新后执行过期动作。

## 9. 功能需求：删除入口调整

### 9.1 FR-DEL-001：移除节点级右上角删除按钮

- `render()` 不再为节点头部 `.node-head` 或 `.floating-node-actions` 输出 `.node-delete`。
- 单媒体节点不再在右上角输出 `.image-delete`；如果仍需要“只移除内容、保留空节点”的能力，应把它作为右键菜单中的“移除图片内容”提供。
- 删除节点保留三种入口：右键菜单、`Delete/Backspace` 快捷键、其他已经明确表达删除语义的管理操作。
- 区块颜色按钮、节点缩放手柄、端口和图片浮动编辑工具不受影响。
- 多图节点内每个缩略图的 `.image-delete` 属于“删除此媒体”的内容级操作，首期保留；它不能删除整个节点。

### 9.2 FR-DEL-002：删除反馈与撤销

- 右键删除不额外弹确认框，以保持与现有 `Delete` 一致；删除后提供短时 Toast“已删除，可撤销”。
- 多选删除显示节点数量。
- “删除区块及内容”必须显示完整危险文案；如果区块包含内容，可在菜单项副文案中显示内容数量。
- 所有删除路径都必须进入现有撤销栈并触发画布保存。

## 10. 功能需求：Figma 式指针与抓手

### 10.1 FR-NAV-001：工具状态模型

画板需要显式维护：

- `baseTool`：`pointer`、`hand`、`brush`、`text`、`section` 之一。
- `temporaryPan`：是否因空格或鼠标中键临时进入抓手。
- `effectiveTool`：`temporaryPan` 为真时是 `hand`，否则等于 `baseTool`。

要求：

- 每次进入智能画板默认 `baseTool = pointer`，本期不跨页面刷新持久化上次工具。
- 任意时刻只有一个基础工具处于激活状态。
- 临时抓手不改变基础工具；释放后恢复临时切换前的工具。
- 页面失焦、浏览器切换标签或指针异常中断时必须清理临时按键状态，避免抓手卡死。

### 10.2 FR-NAV-002：指针模式

- `V` 切换到指针模式，并退出常驻抓手、画笔、文字和区块工具。
- 工具栏“指针”按钮激活，Tooltip/Title 改为“指针 (V)”。
- 指针模式下：
  - 单击节点选择节点。
  - 拖动节点非交互区域移动节点；多选时移动整个选区。
  - 节点端口、缩放手柄、输入框和内部按钮继续执行原有操作。
  - 单击画布空白区域清除选择。
  - 左键拖动画布空白区域不平移视口。
  - 空白区域普通左拖使用选框选择节点，以符合指针工具预期。
- 为兼容现有项目快捷键：
  - `Shift + 左拖` 继续执行连线擦除，优先级高于选框。
  - `Cmd/Ctrl + 左拖` 和按住 `R` 左拖继续可以框选，作为兼容入口保留。
  - `Alt + 拖动节点`、`Alt + Shift + 拖动节点` 的复制语义保持不变。

### 10.3 FR-NAV-003：常驻抓手模式

- `H` 切换到常驻抓手模式，直到用户选择其他工具或按 `V`。
- 工具栏在指针旁新增“抓手”按钮，Title 为“抓手 (H)”，并准确反映激活状态。
- 常驻抓手模式下：
  - 光标静止时为 `grab`，拖动时为 `grabbing`。
  - 左键拖动画布空白区域平移视口。
  - 左键拖动节点的非交互表面也平移视口，不移动、不复制节点。
  - 单击节点非交互表面不改变选择。
  - 节点内输入框、按钮、媒体播放控件、弹窗和侧栏保持可操作，不能因抓手而无法输入或点击。
  - 右键节点仍可打开上下文菜单，并按第 8.2 节更新选择范围。

### 10.4 FR-NAV-004：空格临时抓手

- 当焦点不在可编辑控件中时，按下空格立即设置 `temporaryPan = true`。
- 空格按住期间显示抓手光标；左键可从空白区域或节点非交互表面开始平移。
- 松开空格恢复原 `baseTool`，包括恢复指针、画笔、文字或区块工具的视觉状态。
- 在输入框、文本域、下拉框、`contenteditable`、提示词编辑器和循环变量编辑器中，空格只输入空格，不切换抓手。
- 已经开始的节点拖动、尺寸调整、画笔笔画、区块绘制或连线手势不被中途按下的空格接管；需在当前手势结束后才能临时平移。
- `keydown` 重复事件不得重复初始化状态；`keyup`、窗口 `blur` 和页面隐藏都能结束临时抓手。

### 10.5 FR-NAV-005：鼠标中键临时抓手

- 在画板内容区域按下鼠标中键立即进入本次手势的临时抓手，无需先选择工具。
- 中键拖动可从空白处或节点表面开始，并始终只平移视口。
- 松开中键后恢复原 `baseTool`。
- 中键手势不改变节点选择、不触发节点拖动、不打开浏览器自动滚屏。
- 弹窗、侧栏、Composer、工具栏和可滚动文本区域中的中键行为不由画板接管。

### 10.6 FR-NAV-006：手势优先级

同一指针事件只允许一个手势生效，优先级从高到低为：

1. 弹窗、面板、输入框和显式控件自身交互。
2. 已经开始的裁剪、绘画、尺寸调整、端口连线等专用手势。
3. 鼠标中键临时抓手。
4. 空格临时抓手。
5. 常驻抓手。
6. 指针模式的节点移动、选框、连线擦除等操作。
7. 画笔、文字、区块工具自己的创建操作。

如果基础工具是画笔、文字或区块，按住空格时临时抓手优先；释放后继续原工具，但不会补发被临时抓手消费的点击。

### 10.7 FR-NAV-007：状态视觉和帮助文案

- 工具栏拆分为“指针 (V)”和“抓手 (H)”两个按钮，二者不会同时激活。
- 当前基础工具按钮使用现有 active 样式；空格/中键临时抓手时抓手按钮可显示临时激活态，但不能改变 `aria-pressed` 所代表的基础工具状态，或使用单独的 `data-temporary-active` 表达。
- 画板根节点根据状态切换语义 Class，例如 `tool-pointer`、`tool-hand`、`temporary-pan`、`panning`。
- 快捷键弹窗更新：
  - `Cmd/Ctrl + D`：创建所选节点副本。
  - `V`：切换到指针。
  - `H`：切换到抓手。
  - `Space`：按住临时抓手。
  - `鼠标中键`：按住并拖动临时平移。
  - `指针 + 空白拖动`：框选，不再写“拖动画布”。
- 中英文 i18n 同步补齐，不能只写死中文。

## 12. 数据、接口与权限要求

### 12.1 数据变更

- 通用菜单、指针/抓手状态不要求修改画布持久化 Schema。
- 替换图片沿用现有 `node.images[imageIndex]` 结构。
- 再次生成读取节点现有 `runPrompt`、`runModelPrompt`、`runSettings`、`runInputRefs` 和 `runAt`；本期不新增第二套生成历史 Schema。
- 反推结果默认只存在于结果面板；用户选择创建提示词节点后，才作为普通 `smart-prompt` 持久化。
- `baseTool` 本期只存在前端内存，不写入画布或 `localStorage`。

### 12.2 接口复用与新增

| 能力 | 处理方式 |
|---|---|
| 复制/粘贴/删除 | 纯前端复用现有函数，之后走现有画布保存。 |
| 再次生成 | 前端从节点生成快照重建请求，复用当前各引擎生成接口和任务查询流程。 |
| Selection / Group 操作 | 纯前端复用现有编组、拆分、容器成员和画布保存逻辑。 |
| 加入资产 | 复用现有全局资产库和本地素材接口。 |
| 替换图片 | 复用现有媒体上传接口，再更新节点媒体项。 |
| 图片反推 | 新增画板受控图片反推接口，服务端复用现有视觉模型函数。 |

### 12.3 权限

- 只有具备当前画布编辑权限的管理员或设计师可以执行右键菜单中的写操作。
- 服务端新增反推接口必须重新校验当前登录用户对 `canvas_id` 的访问权，不能信任前端传来的节点数据或绝对文件路径。
- 加入资产沿用资产库权限；没有写权限时菜单项禁用或接口返回 403。
- 分享 Token 不授权反推、替换、复制到工作台、加入资产或删除。

## 13. 异常与边界场景

- 菜单打开后目标节点被协作更新删除：执行前再次按 ID 查找；找不到则关闭菜单并提示“节点已不存在”。
- 菜单打开后画布发生缩放或平移：立即关闭菜单，避免锚点与目标错位。
- 剪贴板节点引用已经不存在的外部节点：粘贴时只恢复复制集合内部的有效连线。
- 多图节点右键后某图片被删除：内容级操作执行前再次校验索引和 URL；不再盲目操作后继图片。
- 反推期间删除节点：允许请求自然结束，但不再自动选中或写回已删除节点；结果面板可仅保留复制文本能力。
- 替换图片上传成功但保存画布失败：本地节点保持可撤销，沿用现有保存冲突合并和重试机制。
- 资产保存部分成功：不得把整体显示为全成功；列出成功数与失败数。
- 空格键在 Composer 中输入、下拉选择和按钮聚焦时不得滚动页面，也不得进入抓手。
- 常驻抓手下右键不应先触发节点拖动；右键菜单关闭后仍保持抓手模式。
- macOS `Ctrl + 单击` 可被浏览器解释为右键，应按 `contextmenu` 统一处理；不能与当前 `Cmd/Ctrl + 拖动框选` 混淆。

## 18. 产品决策与默认假设

- “指针状态不能在画布内移动”解释为：不能通过拖动画布空白处平移视口；指针仍可拖动节点本身，这与 Figma 的 Move/Pointer 工具一致。
- 为更接近 Figma，指针模式下普通左拖空白处用于框选；项目特有的 `Shift + 拖动` 连线擦除继续保留。
- “节点右上角删除按钮”包含节点级删除按钮和单媒体节点右上角的内容删除按钮；二者都移除。多图内部每个缩略图的单媒体移除控件暂时保留，并使用不同文案区分。
- “加入我的资产”首期只覆盖媒体资产；提示词继续保存到提示词预设/提示词库。
- 图片反推结果先进入独立结果面板，由用户决定复制、填入 Composer 或创建提示词节点，不自动改写节点或草稿。
- “再次生成”默认复用该结果自己的生成快照并产生新的兄弟结果；“以此为参考继续生成”是另一个需要用户编辑的新流程。
- Selection 不是持久分组，不使用“解绑”；不同结构分别使用“取消选择、拆分为独立节点、解散分组、移出分组、仅删除区块”。
- 工具状态只在当前页面会话中生效，重新打开画板仍默认指针。
