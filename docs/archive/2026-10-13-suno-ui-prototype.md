## 要解决的问题

现有功能覆盖完整，但第一次创作前有平台、模型、创作方式、简单/详细模式等多层选择。三栏中的表单、结果和历史要求用户自行建立对应关系；格式导出记录又容易被理解成新作品。这些是依据现有页面作出的可用性评估，不是用户测试的统计结果。

用户先要求依据《Don't Make Me Think》和《写给大家看的设计书》检查并制作 Demo，随后明确选择方案 B，并要求参数直接显示，不放在“更多设置”。B 的重点是创作和曲库分开；参数在当前创作页按用途分组，不增加隐藏菜单。

| 原问题 | 原则 | 选定方案 B 的处理 |
| --- | --- | --- |
| 输入想法前先理解多种模式 | 减少需要解释的选择 | 首要问题是“想做什么音乐”；是否加入参考由添加音频自然表达 |
| 参数入口难找 | 识别优先于记忆、明确标签 | 基础设置、音乐偏好、精细控制全部展开；无“更多设置”与折叠区 |
| 创作、结果、历史同时争夺注意 | 对比、亲密性 | 顶部只有创作音乐 / 我的音乐；生成后进入我的音乐查看两首结果 |
| 长表单后难以找到提交操作 | 位置可预测、对比 | 唯一主操作“生成音乐”固定在卡片底部可视位置 |
| 相似功能外观不统一 | 重复、对齐 | 复用公共 ic-* 控件、Design Tokens 和共享中英文资源；表单按统一列对齐 |
| 音频格式导出混进作品列表 | 按用户任务组织 | 同一作品的可下载格式收在歌曲下载弹窗；已有历史导出归入来源歌曲 |

原则来源：[Steve Krug 官方书页](https://sensible.com/dont-make-me-think/)、[Pearson《The Non-Designer's Design Book》第四版](https://www.pearson.com/en-us/subject-catalog/p/Non-Designer-s-Design-Book-The-4th-Edition/P200000000691?view=educator)。未引用书中长段原文。

## 可评审范围

- `npm run prototype:music` 启动，只监听 `127.0.0.1:18886`。
- [打开 Demo](http://127.0.0.1:18886/?prototype=music&variant=B)。同一页面支持既有 App Shell；只有本机明确带 `prototype=music` 的地址才加载演示模块，普通音乐入口保持当前功能。
- 用户选择后，演示固定为 B；删除了 A/C 切换器。
- 桌面左侧创意、歌曲/纯音乐、参考音频和歌词；右侧直接展开参数。窄窗口依次向下排列。
- 参数包括歌名、模型、平台、格式、曲风、排除风格、人声、变化程度、风格强度、新奇程度、参考强度、时长、人设与 Max。
- 未启用的精细参数保留位置并禁用；无参考音频时参考强度不可用，添加参考后人设与指定时长不可用。对应现有 Provider 能力，不能把灰色控件误解成接口已经支持。
- 1–4 首本地参考、试听、移除、创作/曲库切换、模拟生成、搜索、设置复用、下载格式选择可操作。所有 Demo 写入只在内存，刷新清空；音频不上传、不提交收费请求。
- 独立演示服务器只允许 GET/HEAD，提供静态资源和模拟身份/空历史。它不读取实际账号、密钥或工作区。
- 无历史时展示示例曲目；试听使用一段原创合成 WAV，仅用于验证播放器。模拟生成的两个版本使用同一段示例音频，不表示生成质量。
- 在已经登录的真实本机应用中进入同一演示参数地址，可以 GET 读取所属账号历史和音频；原本的权限边界继续由服务端执行。
- 真实历史下载链接按零起始的结果索引读取；格式转换仅演示反馈，没有创建新转换文件。Demo 不验证真实付费生成或转换。

## 验证与后续边界

已在真实浏览器检查：默认 B 页、参数直接展开、英文深色、中文切换、窄窗口无横向溢出、键盘调整滑块、歌名编辑、模拟生成进入曲库、试听、下载格式弹窗；参数复用和最终检查结果记录在 LAZ-85。

默认工作台、文档地图、前端资源和 i18n 回归使用项目 Python 3.12 环境；共享 i18n 与资源指纹按仓库命令检查。默认关闭的通用缓存升级浏览器 gate 不属于本次 Demo 验收。

这是页面布局与任务流程评审，不代表所有用户无需学习，也不承诺真实模型参数的每一种组合已验收。后续正式接入时，应把选定结构移入现有音乐实现并重新跑生成、参考、历史、下载与恢复测试；不应直接把演示计时器和示例数据当作生产实现。

## 正式接入结果（2026-10-14）

用户确认“通过 demo，切换为扣费的真实环境”。布局已移入正式 `lab.html` 与 `music-lab.js`，沿用已有真实 API、Run 生命周期、计费去重、参考托管和 Managed Media 保存；演示仍明确隔离。
生成参数直接展开，创作/曲库分开；参考由加入文件自然启用。统一一个内容输入，根据人声/歌词来源显示主题、描述或歌词，避免同时填写两份内容却有一份被忽略。
曲库中直接试听和下载，导出归入来源记录，详情弹窗承载歌词、冻结参数与付费格式准备。权威合同与测试入口已收敛到 [Current](../current/suno-music-lab.md)。
